## 1. 软件做什么

软件把眼前的一帧照片变成一句能听的下一步：在哪一侧、近不近、要不要先停下。它不替代导盲杖，不判断能不能过马路，不对用户报米数。

两套客户端共用同一个网关：

| 客户端 | 路径 | 谁在用 |
|---|---|---|
| 微信小程序 | `software/miniprogram/` | 没有眼镜时，举起手机 |
| 眼镜网页 | `software/server/static/glasses/` | 镜头跟着视线，手可以拿东西 |

识别不在手机上，也不在镜框上。两边都把照片交给 FastAPI，再由网关去调远程视觉模型。

造型展示页 `look.html` 只展示白框眼镜，不拍照、不识别。真正干活的是 `index.html` 加 `app.js`。

## 3. 一次识别怎么走

```text
小程序或眼镜页
  拍照（实时约 2.5 秒一帧，或精确确认一张）
  可选：用户刚说的一句话
        │
        ▼
POST /infer
  业务口令
  图片 jpg / png / webp，默认最大 5 MB
  question、mode=live|precise、session_id
  可选 spoken_text、distance_band、tof_mm、user_id、client、model_profile
        │
        ▼
同一 session 上一帧还没结束 → 429，丢掉这一帧
        │
        ▼
文本模型判断这句是任务还是闲聊。模型没答出来才用关键词
闲聊：只回短话，不看图，不改主任务
任务：找东西、指路、看价格、看障碍，或寻找还没结束的下一帧
        │
        ▼
读这条 session 的主任务（SQLite，30 分钟不用就过期）
有新的任务句 → 改主任务。找东西时问题写成请在当前照片里寻找
没有新语音但已有主任务 → 继续用上次那条寻找问题
有 tof_mm 就先收成远近档；没有读数就是无法判断
        │
        ▼
任务才调用 primary 视觉模型（当前是 MiMo）
回答收成 JSON：方向、风险、障碍、speech、置信度
高风险时 speech 先说「注意」
寻找任务时补上「正在帮你找……」
live 模式再和上一帧比，避免左右来回改口
        │
        ▼
写回主任务
返回 result + task（decision、question、main_task）
客户端读屏或朗读，高风险可以震动
```

实时和精确的差别只在客户端等待和网关防抖：

| | 实时 `live` | 精确 `precise` |
|---|---|---|
| 频率 | 约 2.5 秒一帧 | 用户再看一眼，一张 | 
| 上一帧没回来 | 丢帧，不排队 | 同样会 429，不叠请求 |
| 播报 | 和上一句差不多就不重复念 | 这一张要说出来 |
| 防抖 | `stabilize_live_result` | 不走这层 |

## 4. 两个客户端

### 4.1 小程序

页面只有两个：`pages/assist/assist`、`pages/settings/settings`。

- 后置摄像头。实时约 2.5 秒一帧，上一帧未完成就丢弃。
- 精确确认用更高质量的一帧。
- 按住说话走 WechatSI，转写在手机里完成，不经过 `/asr`。松开后把文字和当前照片一起 `POST /infer`。
- 按得短于约 400 毫秒，提示按得太短，不推理。
- 每次请求带本机 `session_id`，主任务才能续上。
- 设置页填服务器地址和业务口令。口令放请求头 `X-App-Token`。
- 小程序不保存模型 API Key。

`app.json` 里声明了摄像头和录音权限。插件是 WechatSI `0.3.9`，提供者 `wx069ba97219f66d99`。

### 4.2 眼镜网页

地址：网关同一台机器上的 `/glasses/`。`/glasses` 会 307 到 `/glasses/`。

`index.html` 打开后先看说明，点「开始看」才要摄像头。然后：

- 前置或环境摄像头预览，约 2.5 秒抓一帧，`mode=live`，`client=glasses`。
- 「再看一眼」走 `precise`。
- 「按住，说要找什么」：优先 `MediaRecorder` 录音，再 `POST /asr`。网关没配 ASR 时，改用浏览器 `SpeechRecognition`，拿到文字后同样 `POST /infer`。
- 服务器地址和使用密码可从页面设置，也可从网址参数带入。
- 高风险用短震动。播报用浏览器语音；句子和上一句接近时不重复念。
- 和网关的识别锁是分开的：眼镜带自己的 `session_id`，不会和小程序抢同一把锁，除非两边碰巧共用同一个 session。

造型页 `/glasses/look.html` 是给别人看外观的。上面的「体验一下」链到 `/glasses/`。

## 5. 网关接口

实现都在 `server.py` 的 `create_app`。未设置 `APP_TOKEN` 时不校验口令；设置了就必须带对。口令可以放 `X-App-Token`，或 `Authorization: Bearer`。

| 方法 | 路径 | 口令 | 作用 |
|---|---|---|---|
| GET | `/health` | 不要 | 进程是否活着、模型网关状态、ASR 是否启用、眼镜页文件是否在 |
| GET | `/models` | 要 | 有哪些 profile，默认是哪一个 |
| POST | `/infer` | 要 | 看图。表单上传图片 |
| POST | `/tts` | 要 | JSON `{ "text" }`，返回 mp3。声音是 edge-tts 的 `zh-CN-XiaoxiaoNeural`，最多 200 字 |
| POST | `/asr` | 要 | 上传音频。没配 `ASR_API_BASE_URL` 时返回 501 |
| GET | `/glasses/` | 不要 | 眼镜静态页。页面自己再带口令调接口 |

`/infer` 常见错误：

| 状态 | 原因 |
|---|---|
| 401 | 口令不对 |
| 400 | 不是 jpg/png/webp，或图片是空的 |
| 413 | 超过 `MAX_UPLOAD_BYTES`（默认 5 MB） |
| 429 | 这个 session 上一帧还在识别 |

成功时主要字段：

```text
result.direction        左 / 左前 / 正前 / 右前 / 右 / 未确定
result.risk_level       low / medium / high
result.speech           念给用户的一句
result.distance_band    调用方传来的粗距离，不是米
result.target           正在找的东西
result.main_task
task.decision           new / keep / refine / switch
task.question           这次真正发给模型的问题
profile / model         这次用的模型名
latency_ms
```

## 6. 主任务记忆

文件：`services/task_memory.py`。存在 SQLite，默认 `task_memory.sqlite`，可用 `TASK_DB_PATH` 改。一条记录活 30 分钟。

用户说了一句话之后，先由文本模型分成任务或闲聊。关键词只在模型没答出来时使用。闲聊不进入下面四种判定，也不把这句话记成要找的东西。任务句再做四选一：

| decision | 什么时候 |
|---|---|
| `new` | 还没有主任务，或这句话就是一件新的事 |
| `keep` | 没有新的意图，沿用上一句 |
| `refine` | 还是同一件事，补充了名字或范围，例如「可乐」收成「冰可乐」 |
| `switch` | 目的变了，例如从找可乐改成找门口 |

意图大致是：找入口、找商品、读价格、找收银台、避障、一般帮助。找商品时，发给模型的问题会写成请在当前照片里寻找这个东西。

这样做是为了避免一种已经出现过的失败：语音只播「已经记下」，下一帧视觉仍在说「前方安不安全」。有主任务之后，每一帧实时都继续用那条寻找问题。

规则不负责看图。图里有没有这个东西，只由视觉模型根据这一帧说。

## 7. 模型和清洗

### 7.1 现在用谁

`model_profiles.json`：

- `primary`：MiMo `mimo-v2.5`，`https://api.xiaomimimo.com/v1`，思考关闭，超时 120 秒。
- `backup`：占位地址，没有配真实密钥之前不能当线上备用。

密钥不写进 json，只写环境变量名，例如 `MODEL_API_KEY`。换模型时改 profile 或环境变量，眼镜页、小程序、JSON 字段不用改。

`/infer` 可以临时带 `model_profile` 或 `model`，用来试另一个已配置的 profile。默认仍是 primary。

### 7.2 回答怎么收干净

`minicpmo_runner.py` 把模型原文收成固定字段：

- 方向不在允许列表里，变成「未确定」。
- 风险不在 low / medium / high，变成 medium。
- 米、步数这类精确距离从给用户的句子里拿掉。
- `risk_level = high` 时，speech 以「注意」开头。
- 寻找任务若模型没说「正在帮你找」，`humanize_search_speech` 补上目标，例如「正在帮你找可乐，正前方货架中部较近」。
- 调用方如果传了 `distance_band`，只保留粗档，不换成米。

### 7.3 双模型复核：代码在，主路径没用

`services/fusion.py` 里有 `fuse_results`、`should_verify`。设计是精确模式两个视觉模型并行，实时模式只在没把握或高风险时再问第二个模型。

当前事实：

- profile 里没有 `verify`。
- `infer_image` 只打一次 primary。
- `/infer` 只用了 `stabilize_live_result`，没有调用 `fuse_results`。

所以线上出结论的视觉模型只有 MiMo。没有第二个模型之前，不要对外说已经双模型复核。

若以后接上，speech 仍然只留主模型这一句。第二个模型只改方向、风险、障碍这些字段。左右说反时不要把两个方向平均成一个中间方向。

重点记在手机或眼镜页本机，播报里不说「根据你的习惯」。云端 MemOS 只有设置了 `MEMOS_API_KEY` 才写、才查；留空时不请求外网，识别照常进行。测距硬件还没接上。`tof_mm` 只收成一臂内、较近、较远或无法判断。

## 8. 配置

从 `software/server/.env.example` 复制成 `.env`：

| 变量 | 作用 |
|---|---|
| `MODEL_API_BASE_URL` | 视觉接口根路径，要带 `/v1` |
| `MODEL_NAME` | 默认 `mimo-v2.5` |
| `MODEL_API_KEY` | 视觉密钥 |
| `MODEL_PROFILE` | 默认 `primary` |
| `APP_TOKEN` | 和小程序、眼镜页里填的使用密码一致 |
| `MAX_UPLOAD_BYTES` | 默认 5242880 |
| `BACKUP_MODEL_*` | 备用视觉，可空 |
| `ASR_API_BASE_URL` / `ASR_API_KEY` / `ASR_MODEL` | 眼镜页上传音频时用。空着则 `/asr` 返回 501 |
| `TASK_DB_PATH` | 主任务库文件 |
| `CHAT_MODEL_API_BASE_URL` / `CHAT_MODEL_NAME` / `CHAT_MODEL_API_KEY` | 可选闲聊文本模型。留空则闲聊仍用 MiMo，只发文字 |
| `MEMOS_API_KEY` / `MEMOS_BASE_URL` | 可选云端记忆。留空则关闭 |

本地：

```powershell
cd software/server
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-server.txt
copy .env.example .env
python server.py --host 127.0.0.1 --port 8000
```

然后打开 `http://127.0.0.1:8000/glasses/`。小程序用微信开发者工具打开 `software/miniprogram`，设置页填同一地址和口令。

部署步骤在 `software/DEPLOY.md`。服务不要直接把 8000 端口暴露到公网，前面用 HTTPS 反代。

## 10. 改软件时不要动坏的边界

- 模型密钥只留在服务器环境变量。
- 换视觉模型只改 profile，不改小程序和眼镜页的字段名。
- 没有 `verify` 配置之前，不要在主路径上并行第二个模型。
- 实时帧必须能丢。上一帧没结束就再排队，用户听到的是几秒前的画面。
- 给用户的句子保持短，并且不出现米、步数。
- 过马路、替代手杖，不做成功能，也不写成已支持。
