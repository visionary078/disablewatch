## 1. 产品定位

「看见下一步」面向盲人与低视力用户，把手机摄像头画面转成**可执行的下一步**，而不是普通看图问答。

起点来自真实使用失败：货架前把画面交给通用视觉对话模型，得到的是「画面里有货架」，而不是「第几排、在哪一侧、要不要先停下」。另一类用户社恐、不愿开口求助，越不出门越不敢出门。因此产品做成**微信小程序**：零额外硬件、扫码即用、自己就能完成选购与出门前的一小步。

视障用户往往无法准确点选任务按钮或编辑文本框。v1.4 增加语音通道：用户用口语说出「帮我找可乐」「收银台在哪」，系统把这句话变成当前识别问题，再对着镜头给出方位与风险。

系统输出：

```text
风险提示
+ 参照物 / 场景
+ 二维方位（左 / 左前 / 正前 / 右前 / 右）
+ 粗接近度与可选距离带
+ 一句适合播报的 speech
```

明确不承诺：

- 替代导盲杖、导盲犬或人工协助；
- 单帧证明通道绝对安全；
- 米、厘米、步数、角度等伪精确度量；
- 过马路决策；
- 完整三维导航或 SLAM。

## 2. 设计原则

1. **行动优先，描述其次。** 输出必须能指导「停下 / 转向 / 靠近确认」，而不是景物作文。
2. **不确定就降级。** 非法方向、看不清目标时归为「未确定」，用画面里真实看到的内容造句，不编造方位。
3. **危险只升不降。** 台阶、车辆、玻璃门、地面障碍优先于找目标。
4. **密钥不出端。** 小程序只访问自有网关，只持业务口令 `APP_TOKEN`。
5. **无障碍优先于炫技交互。** 语音需求用点按开关，不用长按；读屏旁白走独立 live 节点。
6. **相同句子不循环。** 实时模式只在文案真正变化、风险升高，或未确定场景满 4 秒后才再播。

## 4. 系统架构

```text
微信小程序「爱总会看见」
  ├─ 后置摄像头拍照
  ├─ 实时模式约 2.5 秒一帧（上一帧未完成则丢弃）
  ├─ 精确确认：高质量单帧，强制播报
  ├─ 语音说出需求：录音 → /asr → 写入 question → 精确确认
  ├─ 可选端侧粗深度带
  ├─ 屏幕文字结果（每帧更新，不含 aria-live）
  ├─ 读屏旁白（隐藏 .sr-live，该说时才写）
  ├─ 可选应用内 TTS
  └─ 高风险长震动 / 中风险短震
        │ HTTPS + X-App-Token
        ▼
FastAPI 网关
  ├─ 鉴权、上传限制、识别锁 / 语音锁
  ├─ 临时图片用完即删
  ├─ Prompt + 远程视觉模型
  ├─ JSON 归一化与安全清洗
  ├─ 实时结果稳定
  ├─ 可选 /tts
  └─ /asr 语音转写
        │
        ├─ 视觉：小米 MiMo mimo-v2.5
        └─ 语音：OpenAI 兼容 /audio/transcriptions（如 SenseVoice）
```

视觉数据流：

```text
拍照 → 粗深度带（可选）→ POST /infer
     → Prompt + 图像 → 模型 JSON
     → normalize_result → apply_distance_band
     → 实时则 stabilize_live_result
     → 屏幕更新
     → shouldSpeak？→ 读屏 + TTS + 震动
```

语音需求数据流：

```text
点「语音说出需求」→ 提示音结束后开始录音
     → 再点一次结束（最长约 12 秒）
     → POST /asr
     → applySpokenNeed 映射任务与问题
     → 播报「已记下…」
     → 按新问题做一次精确确认
```

## 5. 运行逻辑

### 5.1 任务模板

| 任务 | intent | 问题要点 |
|---|---|---|
| 找入口 | `find_entrance` | 入口方向，先提醒风险 |
| 找商品 | `find_product` | 目标商品方向，先提醒风险 |
| 识别价格 | `read_price` | 看得见的名称与价格，看不清不猜 |
| 找收银台 | `find_cashier` | 收银台方向，先提醒通道障碍 |
| 障碍提醒 | `avoid_obstacle` | 当前是否安全，目标在哪一侧 |

### 5.2 前端主路径

1. 摄像头就绪后展示安全说明（首次），默认可进入实时辅助。
2. **实时辅助**：约 2.5 秒一帧。上一帧未完成则丢弃。
3. **精确确认**：高质量单帧，`mode=precise`，强制播报。
4. **语音说出需求**：点按开始 / 再点结束；录音期间暂停实时辅助，结束后按需恢复。
5. 设置页配置 API 地址、`APP_TOKEN`、应用内 TTS、语速、粗深度。
6. HTTP 429 前端静默丢帧。

### 5.3 后端 `/infer`

表单字段：`image`、`question`、`mode`（`live` | `precise`，其它值按精确确认）、`model_profile`、`distance_band`。

处理顺序：鉴权 → 校验图片 → 识别锁 → 临时文件 → 组 Prompt → 调模型 → 解析 JSON → `normalize_result` → `apply_distance_band` → 实时再 `stabilize_live_result` → 返回。

## 6. 结构化结果

```json
{
  "intent": "find_entrance | find_product | read_price | find_cashier | avoid_obstacle | general_help",
  "scene": "与任务相关的简短场景",
  "target": "用户要寻找或确认的目标",
  "direction": "左侧 | 左前方 | 正前方 | 右前方 | 右侧 | 未确定",
  "proximity": "较近 | 较远 | 已接近 | 无法判断",
  "text_reading": "确认识别到的文字或价格；没有则为空字符串",
  "obstacles": ["确认或疑似存在的障碍物"],
  "risk_level": "low | medium | high",
  "confidence": "low | medium | high",
  "action": "风险优先、简短谨慎的下一步行动提示",
  "speech": "适合中文语音播报的短句"
}
```

网关归一化后附带 `distance_band`：`一臂内` / `较近` / `较远` / `无法判断`。

| 字段 | 清洗规则 |
|---|---|
| `direction` | 不在枚举内则「未确定」；可从 speech/action 回填合法方位 |
| `risk_level` | 非法值视为 `medium`；`high` 时句首加「注意」 |
| `confidence` | 非法值视为 `low` |
| `speech` | 去掉米/厘米/步/角度；禁止「可以直接前进」；套话改为场景描述 |

## 7. Prompt 与安全清洗

系统 Prompt：中文、先危险再方位、方向只用六值枚举、不输出精确度量、不说「可以直接前进」、不能替代辅助器具。

实时模式额外约束：

- `speech` 一句、不超过 30 个汉字；
- 画面变化必须改写，禁止套话；
- 禁止「前方暂未发现明显障碍，请缓慢前行」「未能确认目标」「不确定方向」「请停下重新拍摄」；
- 看不清时用当前画面真实物体造句。

不确定套话改写优先级：合法方向 → 可用场景 → 「继续观察周围。」

## 8. 实时结果稳定

`stabilize_live_result` 只作用于 live：

- 套话优先改写成场景描述；
- 当前方向「未确定」且上一帧有合法方向时，可沿用上一帧方向；
- 新的有效句子必须采用，不得钉死第一帧。

进程内按业务令牌缓存 `LIVE_LAST`。

## 9. 播报与读屏

| 通道 | 行为 |
|---|---|
| 屏幕文字 `resultSpeech` | 每帧更新，不含 `aria-live` |
| 读屏旁白 `spokenLive` | 独立隐藏 live 节点，仅在该说时更新 |
| 应用内 TTS | 句子变化才合成；文件名为 `nextstep-tts-{序号}.mp3` |
| 震动 | 高风险长震，中风险短震 |

`shouldSpeak`（`utils/a11y.js`）：

1. 压缩后的 speech 变了 → 立即播；
2. 风险从非高升到高 → 立即播；
3. 精确确认 → 始终播本次；
4. 句子没变、仍是「未确定」或「继续观察」→ **满 4 秒**才允许再提醒一次（`SPEAK_GAP_MS = 4000`）；
5. 其它相同句子不循环。

v1.3 及更早版本中，未确定场景曾用 8 秒节流。v1.4 改为 4 秒，缩短「一直没声音」的空窗，同时避免 2.5 秒一帧把同一句念碎。

## 10. 语音说出需求

### 10.1 为什么不用长按

读屏用户很难完成「按住说话、松开发送」。因此做成**点一下开始、再点一下结束**。提示音播完后再开麦，避免把「请说出你要找什么」录进识别音频。

### 10.2 前端流程

1. 申请 `scope.record`（麦克风）；
2. 暂停实时辅助；
3. 旁白 / TTS：「请说出你要找什么，说完再点一次。」
4. 提示结束后开始录音（最长 12 秒，超时自动结束）；
5. 上传 `/asr`；
6. `utils/voiceNeed.js` 把口语映射到任务与 `question`；
7. 播报「已记下…」，立即 `captureAndInfer("precise")`；
8. 若录音前开着实时辅助，结束后恢复。

口语映射：

| 用户可能说的词 | 任务 |
|---|---|
| 入口、大门、正门 | 找入口 |
| 收银、付款、结账、服务台 | 找收银台 |
| 价格、多少钱、价签 | 识别价格 |
| 障碍、台阶、安全、能不能走 | 障碍提醒 |
| 其它（如「可乐」「洗发水」） | 找商品，问题写成「请帮我找：…」 |

### 10.3 后端 `/asr`

- Mock 模式返回固定演示文本，便于无密钥联调；
- 生产走 OpenAI 兼容 `POST {ASR_API_BASE_URL}/audio/transcriptions`；
- 同一业务令牌同时只转写一段，冲突返回 429；
- 未配置 `ASR_API_BASE_URL` 时返回 501。

## 12. API 摘要

鉴权：`X-App-Token` 或 `Authorization: Bearer <口令>`。生产必须配置 `APP_TOKEN`。

### 12.1 健康检查

```http
GET /health
```

返回 `status`、`model_gateway`、`asr_enabled`。

### 12.2 可用模型

```http
GET /models
Header: X-App-Token: <业务口令>
```

### 12.3 推理

```http
POST /infer
Content-Type: multipart/form-data
```

| 字段 | 说明 |
|---|---|
| `image` | 必填 |
| `question` | 用户问题 / 任务模板 / 语音转写后的需求 |
| `mode` | `live` 或 `precise` |
| `model_profile` | 可选 |
| `distance_band` | 可选 |

实时丢帧为 HTTP 429。

### 12.4 TTS（可选）

```http
POST /tts
{"text": "注意前方有台阶。入口在右前方。"}
```

### 12.5 ASR（语音需求）

```http
POST /asr
Content-Type: multipart/form-data
字段名：audio
```

成功返回 `{ "text": "帮我找可乐", "latency_ms": 800 }`。

## 15. 质量与测试

## 16. 结论

v1.4 把系统定义为：

```text
小程序采集
+ 语音说出需求
+ 远程视觉理解
+ 结构化方位与风险
+ 安全清洗
```

它补上视障用户「说不出任务、点不准按钮」这一环，同时守住不确定就降级、不替代辅助器具的边界。
