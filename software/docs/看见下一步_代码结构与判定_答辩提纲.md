## 0. 三十秒总览（开场备用）

系统分三层：

```text
微信小程序（拍、录、播）
    → FastAPI 网关（鉴权、记任务、组问题、清洗）
        → 远程视觉模型（只看当前照片，吐 JSON）
```

小程序不碰模型密钥。网关不把「记下主任务」当成已经找到。模型不负责 keep/refine/switch，那是规则。

## 2. 一次请求怎么走（主链路）

### 2.1 三条入口，最后都进 `/infer`

| 用户动作 | 前端 | mode | spoken_text |
|---|---|---|---|
| 实时辅助 | 约 2.5 秒拍一帧 | `live` | 空 |
| 精确确认 | 高质量单拍 | `precise` | 空 |
| 按住说话 | 停实时 → 转写 → 单拍 | `precise` | 有中文 |

对应：`pages/assist/assist.js` 的 `startLive` / `onPreciseConfirm` / `onVoiceRelease` → `captureAndInfer` → `utils/api.js`。

### 2.2 网关 `/infer` 判定顺序（`server.py`）

严格按下述顺序，评委问「先判什么」就背这一条：

```text
1. 校验 APP_TOKEN；非法 401
2. 图片后缀、空文件、过大 → 400 / 413
3. 同一 token 上一帧还在跑 → 429 丢帧（实时防堆积）
4. session_id 取主任务记忆
5. revise_main_task(旧记忆, spoken_text) → new|keep|refine|switch
6. 选定 question_used（见 3.2）
7. format_task_context 写入 Prompt 的 [主任务记忆]
8. MiMo 看图，吐 JSON
9. 用户说过的 target 不准被模型改成「入口」
10. 有语音或已有主任务 → 写回 SQLite
11. humanize_search_speech：补「正在帮你找…」
12. 仅 live：stabilize_live_result，避免每 2.5 秒念「不确定」
13. 返回 result + task
```

### 2.3 前端拿到结果后（`handleInferPayload`）

1. 更新任务芯片、当前问题、主任务文案。  
2. `wrapTaskSpeech`：模型已经在说「正在帮你找」就不再加「已记下」。  
3. `shouldSpeak`：精确模式必播；实时要句子变了或风险升高才播。  
4. 高风险长震动，中风险短震。  
5. 语音确认后恢复实时：**跳过立刻再拍一帧**，避免把刚说的话冲掉。

## 3. 判定树（答辩核心）

### 3.1 意图识别 `detect_intent`

文件：`services/task_memory.py`  
**按元组顺序，先命中先赢：**

| 顺序 | intent | 关键词例子 |
|---|---|---|
| 1 | `find_cashier` | 收银、付款、结账、服务台、买单 |
| 2 | `find_entrance` | 入口、大门、正门、出门、门口 |
| 3 | `read_price` | 价格、多少钱、价签 |
| 4 | `avoid_obstacle` | 障碍、台阶、安全、能不能走、有没有坑 |
| 5 | `find_product` | 找、买、拿、帮我找、有没有、我要 |

为什么收银在找商品前面：避免「我要去结账」被「我要」判成找商品。  
「可乐」没有「找」：走 `looks_like_product_request`，短句、非嗯啊、非安全词 → 仍当 `find_product`。

### 3.2 送给模型的问题 `question_used`

```text
有 spoken_text？
  是 → 用规则生成的 revision.question（寻找指令）
  否 → 会话里已有 previous.question？
        是 → 继续用上次寻找问题（实时帧不能退回「安不安全」）
        否 → 用前端传来的 question
```

**答辩句：** 记下主任务不够，必须把寻找问题跟到后面每一帧。这是试用里「记下了但不找」的根因。

### 3.3 主任务修正 `revise_main_task`

输入：旧记忆 + 本句语音。输出：`decision`。

```text
语音为空
  ├─ 有旧主任务 → keep（实时帧走这里）
  └─ 没有 → new / general_help（默认避障问题）

尚无主任务
  └─ new：本句建任务，build_question 生成寻找句

已有主任务
  ├─ 切换口吻或意图变了，且不是「同意图的补充」
  │     → switch   例：找可乐 → 收银台在哪
  ├─ 补充/追问，或意图相同
  │     → refine   例：再往左边、看到了吗、无糖
  └─ 其它
        → keep     例：含糊一句，不改目的
```

优先级：**switch 先于 refine**；但「意图相同且像补充」时不 switch。  
例如已在找商品，又说「再往左边」：same_intent + refine_like → refine，不是新任务。

| 判定 | 例子 | 模型必须做什么 |
|---|---|---|
| new | 帮我找可乐 | 在当前照片里找可乐 |
| keep | （无新语音 / 含糊） | 继续找原来的东西 |
| refine | 不是这个，再往左 | 仍找可乐，吸收补充 |
| switch | 收银台在哪 | 丢掉可乐，改找收银台 |

规则层做判定，**不另调对话大模型**，为了松开后立刻拍照。

### 3.4 实时要不要出声 `shouldSpeak`

文件：`utils/a11y.js`

```text
精确确认 → 一定播
实时：
  没上一句 → 播
  风险从非高升到高 → 立刻播
  句子变了（去标点后比较）→ 播
  仍是「未确定 / 继续观察」→ 距上次 ≥ 4 秒才再提醒
  否则不播
```

**答辩句：** 视障用户受不了 2.5 秒一句套话。变了再说；危险马上说；不确定节流。

### 3.5 实时句子稳定 `stabilize_live_result`

文件：`services/fusion.py`（这里的 fusion 名字容易误导：主路径只用稳定函数，**没有第二模型**）

```text
方向非法 → 从 speech 里抠方向；再不行沿用上一帧方向
本句是「未能确认 / 不确定方向」套话，且上一句正常、当前非高风险
  → 复用上一句，避免循环念不确定
```

### 3.6 安全清洗 `normalize_result` / `sanitize_guidance`

文件：`minicpmo_runner.py`

| 规则 | 判定 |
|---|---|
| 方向不在六值 | 改为「未确定」 |
| 高风险 | 句首强制「注意」 |
| 米 / 厘米 / 步 / 角度 | 正则换成「无法准确判断的距离」 |
| 「可以直接前进」 | 改成请用辅助工具再确认 |
| 寻找任务 speech 没有「正在帮你找」 | `humanize_search_speech` 补上 |

### 3.7 丢帧与锁

`INFER_LOCKS[token]`：同一业务口令同时只跑一帧。实时 2.5 秒一拍，模型若超过 2.5 秒，新帧 **HTTP 429 直接丢**，不排队。  
**答辩句：** 旧画面不准盖住人已经转头后的新画面。

### 3.8 双模型融合（设计有、桌面主路径没有）

`fuse_results` / `should_verify` 在 `fusion.py`，桌面 `infer_image` **单次调用 MiMo**。  
`model_profiles.json` 没有 `verify`。

若被问「PPT 上的双模型」：

- **精确**：同一张图、同一句寻找问题，主模型 + 验证模型并行，只融合字段。  
- **实时**：主模型先说；低置信 / 未确定 / 高风险才验证。  
- **冲突**：不投票；设计上应降为未确定。  
- **验证模型不对用户说话。**  
- **现状：** 规则和函数在，桌面主路径未接线。不要说线上每帧都在双跑。

## 4. 模块职责一览（追问「为什么不放在模型里」）

| 事 | 谁做 | 为什么 |
|---|---|---|
| 听清「找可乐」 | WechatSI | 端侧快，不占视觉配额 |
| keep/refine/switch | 规则 | 毫秒级，松开就能拍 |
| 在照片里找可乐 | MiMo | 只有它看得见 |
| 口语「正在帮你找」 | Prompt + humanize | 模型会填表；规则兜底 |
| 方向枚举 / 洗米数 | 网关 | 模型爱编精确数字 |
| 该不该再播 | 前端 shouldSpeak | 跟读屏节奏绑定 |
| 密钥 | 仅服务器 | 小程序只持 APP_TOKEN |

## 5. 关键数据结构

模型必须吐的 JSON（再被清洗）：

```text
intent, scene, target, direction, proximity, text_reading,
obstacles, risk_level, confidence, action, speech
```

方向只允许：左侧 / 左前方 / 正前方 / 右前方 / 右侧 / 未确定。  
距离带（端侧可选）：一臂内 / 较近 / 较远 / 无法判断。

接口额外返回 `task`：

```text
session_id, decision, reason, main_task, intent, question, spoken_text
```

记忆库按 `session_id`：intent、target、main_task、question、最近 8 句语音；**30 分钟**无更新过期。

## 6. 模拟答辩（先答一句，再展开）

### 产品

**Q：和豆包看图有什么区别？**  
A：豆包输出描述。我们输出下一步：方位、远近、要不要停。冲突或看不清就降级，不编米数。

**Q：为什么做小程序不做眼镜？**  
A：社恐用户不愿戴显眼设备，也不愿开口求人。微信扫码即用，零硬件。

**Q：能过马路吗？能替代导盲杖吗？**  
A：不能。安全声明写进界面和 Prompt。我们只辅助货架、门口、收银台这类下一步。

### 结构

**Q：端和云怎么分工？**  
A：端负责摄像头、长按录音、读屏和 TTS。云负责鉴权、主任务判定、Prompt、看图、清洗。密钥不出手机。

**Q：一次实时帧为什么可能没声音？**  
A：三种可能：429 上一帧没完被丢；句子没变且未到 4 秒；稳定函数复用了上一句所以前端认为没变。

**Q：为什么 2.5 秒拍一次还要丢帧？**  
A：视觉调用经常超过 2.5 秒。排队会把过时画面播给已经转头的人。丢帧是安全，不是性能偷懒。

### 听与看

**Q：语音是哪个模型？**  
A：转写是微信同声传译，不是 MiMo。MiMo 只看图。听完必须把寻找问题交给 MiMo，否则只是「记下了」。

**Q：为什么 keep/refine/switch 不用大模型？**  
A：松开后要马上拍照。规则足够覆盖「还找可乐 / 改成收银台」。视觉模型再执行寻找。

**Q：「再往左边」为什么不算新任务？**  
A：意图仍是 find_product，且命中 refine 词。switch 被挡住。主任务还是可乐，问题后面追加用户补充。

**Q：「收银台在哪」为什么会丢掉可乐？**  
A：detect_intent 变成 find_cashier，与旧意图不同，走 switch。Prompt 要求按当前主任务回答。

### 双模型（PPT 有、代码要诚实）

**Q：两个视觉模型怎么协作？**  
A：设计上主模型指路、验证模型挑刺。精确并行、实时先说。验证不对人说话。方向冲突不投票。桌面主路径目前只跑 MiMo，融合函数已写好未接线。

**Q：会不会两张嘴？**  
A：不会。TTS 只播融合后或主模型的一句 speech。

**Q：高风险为什么不等验证？**  
A：台阶已经出现，沉默比不完整答案更危险。先播注意，验证后台或下一帧再纠。

### 安全

**Q：幻觉怎么防把人带沟里？**  
A：方向枚举钳制；冲突未确定；禁止米步角度；「可以直接前进」改写；高风险强制「注意」；不承诺过马路。

**Q：图片和密钥？**  
A：图在网关落临时文件，推理完删除。模型 Key 只在服务器环境变量。小程序只有 APP_TOKEN。

### 局限（主动说，显得扎实）

1. 二维语义方位，不是世界坐标。  
2. 距离带是粗估计，不是雷达。  
3. 口音、噪声下插件可能听不清。  
4. 主任务是规则，极端口语可能判错，用户再说一句即可 switch。  
5. 双模型验证尚未在桌面主路径双跑。  
6. 真人视障规模试验仍是下一步，不编造数据。

## 7. 现场演示对照（评委盯屏幕）

建议口播顺序与代码一致：

1. 打开实时：约 2.5 秒一帧，报眼前方位，不循环「不确定」。  
2. 按住说「帮我找可乐」：应听到「正在帮你找可乐…」，状态栏同步这句话。  
3. 不再说话，继续实时：仍应围绕可乐，而不是变回避障套话。  
4. 再说「收银台在哪」：应 switch，改找收银台。  
5. 精确确认：强制播报当前帧。  
6. 停播 / 重播：TTS 可打断、可重复上一句。

失败时先查这三处：公众平台是否添加 WechatSI；APP_TOKEN 是否一致；网关是否重启过（主任务与口语化在服务端）。

## 8. 一页纸背诵版

```text
端：拍 / 听 / 播
云：判任务 / 组问题 / 看图 / 清洗

意图：收银 → 入口 → 价格 → 避障 → 找商品
任务：new 建立；keep 沿用；refine 补充；switch 换目的
问题：有语音用新寻找句；没语音用上次寻找句
播报：变了才说；升高风险马上说；不确定 4 秒节流
安全：六值方向；风险只升；不准米数；密钥不出端
模型：MiMo 看图说话；微信听；规则记任务
双模型：函数在 fusion.py，桌面 infer 仍单模型
```
