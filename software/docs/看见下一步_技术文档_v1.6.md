## 1. 产品定位

「看见下一步」面向盲人与低视力用户，把手机摄像头画面转成**可执行的下一步**，而不是普通看图问答。

起点来自真实使用失败：货架前把画面交给通用视觉对话模型，得到的是「画面里有货架」，而不是「第几排、在哪一侧、要不要先停下」。另一类用户社恐、不愿开口求助。因此做成微信小程序：零额外硬件、扫码即用。

系统输出：

```text
风险提示
+ 参照物 / 场景
+ 二维方位（左 / 左前 / 正前 / 右前 / 右）
+ 粗接近度与可选距离带
+ 一句适合播报的 speech（口语：正在帮你找什么）
+ 当前主任务
```

明确不承诺：替代导盲杖 / 导盲犬；单帧证明通道安全；米级测距；过马路决策；SLAM。

## 2. 先分清：系统里其实有两层「双模型」

评委或后续开发者容易把两件事混成一件。它们解决的问题不同，接线状态也不同。

| 层次 | 两个角色 | 当前状态 | 协作要解决的问题 |
|---|---|---|---|
| **A. 听与看** | WechatSI 转写 + MiMo 看图 | **已落地** | 用户说了要找什么，看图模型必须立刻在画面里找，而不是只「记下」 |
| **B. 主视觉与验证视觉** | MiMo 主推理 + Qwen3-VL（或其它异构视觉）复核 | **设计完成、桌面未接线** | 单模型会看错方向、漏报风险；双跑又会拖慢实时、抢播报、投票猜方向 |

第 3 节写清 A；第 4 节写清 B。B 没有接上之前，线上真正出结论的视觉模型只有 **MiMo `mimo-v2.5`**。

## 3. 第一层协作（已落地）：听的模型 与 看的模型

### 3.1 为什么必须拆开

找可乐、找入口、找收银台，本质是**看图定位**。同声传译听不见货架，也看不见玻璃门。  
反过来，MiMo 听不见用户说话。若只把转写结果显示在界面上、不改发给它的问题，它会继续按默认任务「判断前方是否安全」说话。

试用中出现过的失败形态：

```text
用户：帮我找可乐
系统播报：已记下主任务：帮我找可乐
随后实时画面：正前方货架中部较近
```

用户以为系统在找可乐，实际只是**规则层存了句子**，视觉模型仍在报通道。这不是 ASR 没听清，是**两个模型没有在同一条任务上协作**。

### 3.2 正确分工

| 角色 | 组件 | 只做什么 | 禁止做什么 |
|---|---|---|---|
| 听 | WechatSI 0.3.9 | 把按住说话转成中文文本 | 不看图、不定方位、不编造「正在找」 |
| 记 | `task_memory.py` 规则 | `new / keep / refine / switch`，生成寻找问题 | 不替代视觉；不把「记下」当成已经找到 |
| 看与说 | 小米 MiMo `mimo-v2.5` | 在**当前照片**里找目标，输出方向 / 风险 / 口语 speech | 不把主任务改回旧目标；不说「已记下主任务」 |

主任务判定用规则而不是再调一个对话大模型，是为了**松开后尽快拍照推理**。语音修正延迟应低于一次视觉调用。

### 3.3 协作时序

```text
按住说话
  → WechatSI 转写
  → revise_main_task：new | keep | refine | switch
  → 生成「请在当前照片里寻找「可乐」」这类问题
  → 写入 [主任务记忆]
  → 同一张当前照片交给 MiMo
  → MiMo 必须执行寻找，speech 用「正在帮你找可乐，…」
  → 写回 SQLite
  → 之后每一帧实时辅助：即使没有新语音，也继续用这条寻找问题
```

关键约束（v1.6 已改）：

1. 有 `spoken_text` 时，送给 MiMo 的 `question` **必须是规则生成的寻找问题**，不能是界面上残留的「前方安不安全」。
2. 没有新语音但会话里已有主任务时，实时帧 **沿用上次寻找问题**，不能退回默认障碍模板。
3. 用户指定的 `target`（如可乐）**不得被模型随口输出的「入口」覆盖**。
4. 前端不再播「已记下主任务」；若模型没说「正在帮你找」，网关会补上口语。
5. 语音精确确认播完后，实时辅助**不要立刻再拍一帧**把这句话冲掉。

### 3.4 这一层的协作问题（以及对策）

| 问题 | 若不管会怎样 | 对策 |
|---|---|---|
| 听完不看 | 只播「记下了」，画面里并不找 | 转写后立刻 `/infer`，问题改成寻找指令 |
| 看完丢掉听 | 下一帧又变回避障套话 | 实时帧读取 SQLite 主任务问题 |
| 两个都想说话 | 「记下」+ 机械 JSON 叠在一起 | 只让 MiMo 的 speech 出声；规则不报账 |
| 听错了 | 找错商品 | 用户再说一句即可 switch；不在视觉里猜用户原意 |
| 听对了但图里没有 | 编造已经看到 | 允许「还在帮你找，眼前是货架」；降低 confidence |

这一层**不需要**第二视觉模型。第二视觉模型解决的是「看错了」，不是「没去看」。

## 4. 第二层协作（预留）：主视觉 与 验证视觉

### 4.1 为什么要两个视觉模型

单模型看图会在视障场景里犯三类错，而用户无法自己核对画面：

1. **方向看反**：把左侧说成右侧。
2. **风险看低**：漏报台阶、玻璃门、车辆。
3. **目标幻觉**：没看到可乐却说可乐在正前方。

用**另一家厂商**的视觉模型做复核，比同厂两个 twin 更有用：验证侧应当「挑刺」，而不是复述主模型文风。

设计角色：

| 角色 | 建议模型 | 职责 |
|---|---|---|
| 主视觉 | 小米 MiMo `mimo-v2.5` | 找目标、给方位、写口语 speech、实时先出结果 |
| 验证视觉 | 硅基流动 `Qwen/Qwen3-VL-30B-A3B-Thinking`（设计稿） | 核对方向、抬高风险、检查目标是否真的可见、价格/文字不一致则删掉数字 |

部署包里曾试验过把 `verify` 配成 MiniMax-M3。无论选谁，原则不变：**验证模型不负责对用户说话**。

### 4.2 当前接线事实（必须写清）

| 位置 | 事实 |
|---|---|
| 桌面 `model_profiles.json` | 只有 `primary`（MiMo）和占位 `backup`，**没有 `verify`** |
| 桌面 `minicpmo_runner.infer_image` | 同步单次调用，**不会**并行第二模型 |
| 桌面 `services/fusion.py` | `fuse_results` / `should_verify` / `FusionConfig` 已实现，**主路径未调用** |
| 另一份部署包 | 有 `infer_image_async`、`verify` profile、条件并行；**不等于**当前桌面仓库已上线 |

因此：v1.2 文稿中的「条件双模型验证」是**目标架构**。v1.6 桌面主路径仍是 **MiMo 单模型 + 规则记忆 + 端侧转写**。

### 4.3 若接上，正确的协作方式

不能「两张图各问一遍、把两段话拼起来」。必须字段级融合，并且按模式拆等待预算。

**精确确认（可以等）**

```text
同一张图、同一条寻找问题
  ├─ 主模型 MiMo     ┐
  └─ 验证模型 Qwen   ┘ 并行
        ↓
   只融合：direction / risk_level / obstacles / text_reading / confidence
        ↓
   speech 仍以主模型口语为底，再套安全规则
        ↓
   一次播报
```

**实时辅助（不能等）**

```text
主模型先返回并播报（预算跟 2.5 秒巡视走）
  └─ 仅当 should_verify 为真时，后台验证
        ↓
     结果写入会话，供下一帧纠偏
     不在本帧中途改口抢播
```

`should_verify` 现有条件：主结果缺失、`confidence = low`、`direction = 未确定`、`risk_level = high`。  
高风险帧：**先播「注意 / 停下」**，不要为了等验证而沉默。

### 4.4 融合规则（代码已有，主路径未用）

`fuse_results(primary, verify)` 输出四类一致度：

| agreement | 含义 | 对用户的影响 |
|---|---|---|
| `consistent` | 方向相同且风险相同 | 可上调 confidence |
| `similar` | 方向相同风险不同，或方向相邻（如右前 vs 右侧） | 保留主模型方向，风险取高 |
| `conflict` | 方向跨度 ≥ 2（如左侧 vs 右侧） | **不投票、不取平均** |
| `degraded` | 一侧超时或失败 | 置信度降为 low，能播的先播 |

共同安全规则：

- **风险只升不降**，取两边较高者。
- **障碍并集**，验证看到的台阶不能被主模型「没看到」抹掉。
- **价格 / OCR**：两边数字不一致则不播具体数字。
- **speech 只出一张嘴**：验证模型的长思维链、英文、填表腔不得进 TTS。

关于方向冲突，需要单独写清**设计意图与当前函数的差异**：

| | 设计意图（v1.2 / v1.3 文稿） | 当前 `fuse_results` 实现 |
|---|---|---|
| 左右明显矛盾 | 降为「未确定」，宁可说看不清 | 保留主模型已确定方向，confidence 降为 low |

这是接线前必须拍板的协作问题：视障场景下，**说错左右比说「未确定」更危险**。建议接线时改回「冲突 → 未确定 + 请停下确认」，不要让两个模型投票选出一个方向。

### 4.5 第二层的协作问题（不接或接错都会出）

| 问题 | 表现 | 为什么不能这么做 | 正确做法 |
|---|---|---|---|
| 两张嘴 | 先说可乐在右前，两秒后改口在左前 | 用户无法判断该信哪一次 | 本帧只播主模型；验证只改下一帧或精确模式融合后的一句 |
| 验证抢任务 | 主模型在找可乐，验证按默认「前方安全吗」看图 | 验证会把寻找结果「纠正」成货架/通道 | **两模型必须吃同一条寻找问题 + 同一段主任务记忆** |
| 实时被拖死 | Qwen Thinking 一次 10 秒以上 | 2.5 秒巡视堆积，锁 429 丢帧 | live 最多等 `live_verify_wait`（设计约 2 秒），超时当 degraded |
| 高风险还在等 | 台阶已经出现，仍等第二模型 | 危险窗口被验证延迟吃掉 | high 先播停下，验证后台跑 |
| 投票猜方向 | 左 vs 右取「更像中间」 | 没有第三只眼睛，平均方向没有物理意义 | 冲突就未确定，让用户停下 |
| 验证改写 speech | 把「正在帮你找可乐」改成填表句 | 无障碍体验回退 | 验证只动结构化字段，口语后处理仍走主模型 / `humanize_search_speech` |
| 配置了 backup 当 verify | 占位 URL 一直失败 | 每次 degraded，confidence 永远 low | 没有真实 verify profile 就 `fusion.mode = none`，单模型干净出结果 |
| Thinking 关不掉 | 验证侧又慢又贵 | 实时路径不可用 | 验证优先选非 Thinking 视觉版；主模型保持 `thinking.disabled` |

### 4.6 启用验证模型的接线清单

桌面主路径要真正双跑，至少同时满足：

1. `model_profiles.json` 增加可用的 `verify`（真实 `base_url` / `model` / `api_key_env`）。
2. 增加 `fusion` 块：`precise_mode=parallel`，`live_mode=conditional`，`verify_profile=verify`。
3. `infer_image` 改为异步：精确并行；实时主模型先返回、条件验证。
4. `/infer` 把**同一** `question_used` 和 `[主任务记忆]` 传给两侧。
5. 响应增加 `fusion.mode / models / agreement`，便于调试，但不要把 agreement 念给用户听。
6. 方向冲突策略与文稿对齐后再上线。
7. 真机验收：精确确认应能看到两个模型名；实时在稳定低风险帧不应明显变慢。

未完成以上任一项，对外仍应称为**单主模型**。

## 5. 系统架构（当前落地）

```text
微信小程序「爱总会看见」
  ├─ 后置摄像头
  ├─ 实时约 2.5 秒一帧（上一帧未完成则丢弃）
  ├─ 精确确认：高质量单帧
  ├─ 按住说话：WechatSI 录音+转写
  ├─ 读屏旁白 / 可选 TTS / 风险震动
        │ HTTPS + X-App-Token
        ▼
FastAPI 网关
  ├─ 鉴权、上传限制、识别锁
  ├─ 主任务记忆（session_id → SQLite）
  ├─ keep / refine / switch 判定
  ├─ Prompt + 当前画面 → 仅主视觉模型
  ├─ JSON 归一化、口语化、安全清洗
  └─ 可选 /tts、备用 /asr
        │
        ├─ 已接：小米 MiMo mimo-v2.5
        ├─ 已接：微信同声传译（端侧，不经网关看图）
        └─ 未接：验证视觉（Qwen3-VL 等）
```

视觉数据流：

```text
拍照 → 粗深度带（可选）→ POST /infer
     （question + session_id + 可选 spoken_text）
     → 读取主任务记忆 → 判定修正
     → 组 Prompt → MiMo JSON → 清洗与口语化
     → 写回主任务库
     → 屏幕 + 读屏 + TTS
```

语音数据流：

```text
touchstart 按住 → WechatSI start
touchend 松开 → 中文文本
  → 拍当前画面
  → POST /infer（spoken_text + session_id + image）
  → 播报「正在帮你找…」与方位
```

## 6. 运行逻辑

### 6.1 任务模板

| 任务 | intent | 问题要点 |
|---|---|---|
| 找入口 | `find_entrance` | 正在帮你找入口 |
| 找商品 | `find_product` | 正在帮你找具体商品 |
| 识别价格 | `read_price` | 看得见的名称与价格 |
| 找收银台 | `find_cashier` | 正在帮你找收银台 |
| 障碍提醒 | `avoid_obstacle` | 当前是否安全 |

### 6.2 前端

1. 摄像头就绪后展示安全说明，默认可进入实时辅助。
2. **实时辅助**：约 2.5 秒一帧。
3. **精确确认**：高质量单帧，强制播报。
4. **按住说话**：录音期间暂停实时；松开后转写并精确确认；结束后恢复实时（不立刻冲掉本句）。
5. 每次推理携带本机 `session_id`。
6. 三个「设置」按钮已删除；长按顶部状态栏进入设置页。

### 6.3 长按录音

按钮是 `view` + `catchtouchstart` / `catchtouchend` / `catchtouchcancel`。

| 事件 | 行为 |
|---|---|
| 按下 | 立刻开麦，「松开结束」，短震动 |
| 松开（≥400 ms） | 停止录音，插件返回文本，再推理 |
| 松开过短 | 提示「按得太短」 |
| 页面隐藏 | 取消录音，不提交 |

**必须**在微信公众平台为小程序添加 WechatSI 0.3.9，否则无法编译、无法录音。

## 7. 主任务上下文库

文件：`services/task_memory.py`。默认 `TASK_DB_PATH=task_memory.sqlite`。30 分钟无更新过期。保存 `intent` / `target` / `main_task` / `question` 与最近 8 句语音。

| 判定 | 含义 | 例子 |
|---|---|---|
| `new` | 尚无主任务，用本句建立 | 「帮我找可乐」 |
| `keep` | 未改变目的 | 「看到了吗」 |
| `refine` | 同一目的的补充 | 「再往左边一点」 |
| `switch` | 目的变了 | 「收银台在哪」 |

判定后把当前主任务写入 Prompt 的 `[主任务记忆]`，并明确要求模型**立刻在画面中寻找**，不要只确认已经记下。

## 8. 结构化结果与播报

方向枚举：左侧、左前方、正前方、右前方、右侧、未确定。  
风险与置信度：low / medium / high。  
距离带：一臂内 / 较近 / 较远 / 无法判断。

清洗：非法方向归「未确定」；高风险句首加「注意」；去掉米/厘米/步/角度；禁止「可以直接前进」。  
口语：寻找类任务 speech 应含「正在帮你找{目标}」。

播报通道：`resultSpeech` 每帧更新但不直接 aria-live；`spokenLive` 该说才写；应用内 TTS 句子变化才合成。  
未确定 / 继续观察最短 **4 秒** 才允许再提醒。

鉴权：`X-App-Token` 或 `Authorization: Bearer`。

| 方法 | 路径 | 说明 |
|---|---|---|

## 11. 质量、测试与已知限制

后端单测覆盖：JSON 解析、非法方向、伪精确度量、高风险「注意」、主任务 new/refine/switch、寻找口语化、语音后再实时仍保持商品目标、`/asr` 合约。融合函数可单测，但桌面 `/infer` 不会双跑。

已知限制：

- 二维语义方位，不是世界坐标；
- 粗距离带，不是 LiDAR；
- 同声传译依赖微信插件与真机麦克风；
- 主任务判定是规则，不是对话大模型；
- **当前视觉主路径为单主模型**；验证模型未接线。

## 12. 结论

v1.6 把协作关系固定成两句话：

```text
1. 听（WechatSI）负责听清要找什么；看（MiMo）负责在当前画面里找，并用人话播报。
   记下主任务不等于已经找到。二者必须共用同一条寻找问题。

2. 第二个视觉模型只做复核，不负责对用户说话。
   精确模式可以并行；实时模式主模型先出。
   方向冲突不投票。风险只升不降。
   桌面仓库在 verify profile 与异步推理接上之前，不得对外称为双模型已上线。
```

当前可演示、可交付的闭环是：

```text
长按语音说出需求
+ 同声传译
+ 主任务记忆（keep / refine / switch）
+ MiMo 看图寻找
+ 口语「正在帮你找…」
+ 安全清洗与句子级播报
```
