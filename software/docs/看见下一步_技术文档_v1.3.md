## 1. 产品定位

「看见下一步」面向盲人与低视力用户，把手机摄像头画面转成**可执行的下一步**，而不是普通看图问答。

起点来自真实使用失败：货架前把画面交给通用视觉对话模型，得到的是「画面里有货架」，而不是「第几排、在哪一侧、要不要先停下」。另一类用户社恐、不愿开口求助，越不出门越不敢出门。因此产品做成**微信小程序**：零额外硬件、扫码即用、自己就能完成选购与出门前的一小步。

系统输出：

```text
风险提示
+ 参照物 / 场景
+ 二维方位（左 / 左前 / 正前 / 右前 / 右）
+ 粗接近度与可选距离带
+ 一句适合播报的 speech
```

明确不承诺：

- 替代导盲杖、导盲犬或人工协助；
- 单帧证明通道绝对安全；
- 米、厘米、步数、角度等伪精确度量；
- 过马路决策；
- 完整三维导航或 SLAM。

---

## 2. 设计原则

1. **行动优先，描述其次。** 输出必须能指导「停下 / 转向 / 靠近确认」，而不是景物作文。
2. **不确定就降级。** 非法方向、看不清目标时归为「未确定」，用画面里真实看到的内容造句，不编造方位。
3. **危险只升不降。** 台阶、车辆、玻璃门、地面障碍优先于找目标。
4. **密钥不出端。** 小程序只访问自有网关，只持业务口令 `APP_TOKEN`。
5. **无障碍与视觉布局分离。** 不改主按钮与画面结构；读屏旁白走独立 live 节点。
6. **相同句子不循环。** 实时模式只在文案真正变化或风险升高时播报。

## 4. 系统架构

```text
微信小程序「爱总会看见」
  ├─ 后置摄像头拍照
  ├─ 实时模式约 2.5 秒一帧（上一帧未完成则丢弃）
  ├─ 精确确认：高质量单帧，强制播报
  ├─ 可选端侧粗深度带（一臂内 / 较近 / 较远）
  ├─ 屏幕文字结果（每帧更新，不含 aria-live）
  ├─ 读屏旁白（隐藏 .sr-live，句子变了才写）
  ├─ 可选应用内 TTS（句子变了才合成）
  └─ 高风险长震动 / 中风险短震
        │ HTTPS + X-App-Token
        ▼
FastAPI 网关（API 版本 2.1.0）
  ├─ 鉴权、上传类型与大小限制
  ├─ 识别锁：同一业务令牌同时只跑一帧（冲突返回 429）
  ├─ 临时文件用完即删
  ├─ 按 mode 组装 Prompt
  ├─ 远程视觉模型调用
  ├─ JSON 围栏解析 + 字段归一化
  ├─ 禁止米/步/角度；高风险句首加「注意」
  ├─ 实时：stabilize_live_result（去套话、可沿用上一有效方向）
  └─ 可选 /tts 合成
        │
        ▼
小米 MiMo mimo-v2.5（OpenAI 兼容 image_url）
```

数据流可以概括为：

```text
拍照 → 粗深度带（可选）→ POST /infer
     → Prompt + 图像
     → 模型 JSON
     → normalize_result
     → apply_distance_band
     → 实时则 stabilize_live_result
     → 屏幕更新
     → shouldSpeak？→ 读屏节点 + TTS + 震动
```

## 5. 运行逻辑

### 5.1 任务模板

设置与主界面共用五类意图（`utils/config.js`）：

| 任务 | intent | 问题要点 |
|---|---|---|
| 找入口 | `find_entrance` | 入口方向，先提醒风险 |
| 找商品 | `find_product` | 目标商品方向，先提醒风险 |
| 识别价格 | `read_price` | 看得见的名称与价格，看不清不猜 |
| 找收银台 | `find_cashier` | 收银台方向，先提醒通道障碍 |
| 障碍提醒 | `avoid_obstacle` | 当前是否安全，目标在哪一侧 |

### 5.2 前端主路径

1. 摄像头就绪后展示安全说明（首次），默认可进入实时辅助。
2. **实时辅助**：`setInterval` 约 2.5 秒调用 `captureAndInfer("live")`。若 `_inferring` 仍为真，本拍丢弃，避免堆积。
3. **精确确认**：用户点击后拍高质量图，`mode=precise`，强制播报本次结果。
4. 实时拍照质量为 `normal`，精确确认为 `high`。
5. 设置页配置 `apiBaseUrl`、`APP_TOKEN`、是否开启应用内 TTS、播报语速、是否启用粗深度。
6. HTTP 429（上一帧仍在识别）前端静默返回，不弹窗打断实时巡视。

### 5.3 后端 `/infer`

表单字段：`image`、`question`、`mode`（`live` | `precise`）、`model_profile`、`distance_band`。

处理顺序：

1. 校验 `X-App-Token` / `Authorization: Bearer`；
2. 仅接受 JPG / PNG / WEBP，默认上限 5 MB；
3. 同一业务令牌若上一帧未结束，返回 429；
4. 图片写入临时文件，推理结束后删除；
5. 按 `mode` 组装 Prompt（实时额外要求一句 ≤30 字、禁止套话）；
6. 调远程视觉模型，从回答中截取 JSON（支持去掉 Markdown 围栏）；
7. `normalize_result`：方向枚举、风险/置信度、清洗伪精确度量；
8. `apply_distance_band`：把端侧粗距离带写入结果，必要时补一句「看起来较近」等；
9. 实时模式再经 `stabilize_live_result`：套话则改写或沿用上一句有效播报，**不把新的有效句子锁死成第一帧**；
10. 返回 `result`、`raw_answer`、`latency_ms`、`profile`、`model`、`usage`。

## 6. 结构化结果

模型被约束为只输出一个 JSON 对象：

```json
{
  "intent": "find_entrance | find_product | read_price | find_cashier | avoid_obstacle | general_help",
  "scene": "与任务相关的简短场景",
  "target": "用户要寻找或确认的目标",
  "direction": "左侧 | 左前方 | 正前方 | 右前方 | 右侧 | 未确定",
  "proximity": "较近 | 较远 | 已接近 | 无法判断",
  "text_reading": "确认识别到的文字或价格；没有则为空字符串",
  "obstacles": ["确认或疑似存在的障碍物"],
  "risk_level": "low | medium | high",
  "confidence": "low | medium | high",
  "action": "风险优先、简短谨慎的下一步行动提示",
  "speech": "适合中文语音播报的短句"
}
```

网关归一化后还会附带 `distance_band`：`一臂内` / `较近` / `较远` / `无法判断`。

字段约束：

| 字段 | 清洗规则 |
|---|---|
| `direction` | 不在枚举内则「未确定」；若 speech/action 中能抽出合法方位，可回填 |
| `risk_level` | 非法值视为 `medium`；`high` 时 speech/action 句首加「注意」 |
| `confidence` | 非法值视为 `low` |
| `proximity` | 非法值视为「无法判断」 |
| `speech` | 去掉米/厘米/步/角度；禁止「可以直接前进」；套话改为场景描述 |

## 7. Prompt 与安全清洗

系统 Prompt 固定要求：中文、先危险再方位、方向只能用六值枚举、不输出精确度量、不说「可以直接前进」、不能替代辅助器具。

实时模式额外约束（`LIVE_SPEECH_HINT`）：

- `speech` 只有一句，不超过 30 个汉字；
- 不朗读价格和长段文字；
- 画面变化必须改写，禁止反复同一句套话；
- 禁止「前方暂未发现明显障碍，请缓慢前行」「未能确认目标」「不确定方向」「请停下重新拍摄」；
- 看不清时用当前画面真实物体造句，例如「正前方货架中部较近」。

`sanitize_guidance` 用正则去掉伪精确度量，并把「可以直接前进」等替换为谨慎表述。

`normalize_result` 若检测到不确定套话，会按优先级改写：

1. 已有合法方向 → 「目标在{方向}。」
2. 有可用 scene → 「看到{场景}。」
3. 否则 → 「继续观察周围。」

## 8. 实时结果稳定

`services/fusion.py` 中的 `stabilize_live_result` 只作用于 **live** 模式：

- 若当前 speech 是套话（「未能确认目标」「不确定方向」「请停下并重新拍摄」等），优先用画面场景改写；
- 当前方向为「未确定」且上一帧有合法方向时，可沿用上一帧方向，避免每 2.5 秒都报「未确定」；
- 若新 speech 是有效新句，**必须采用新句**，不得把旁白钉死在第一帧。

进程内按业务令牌缓存 `LIVE_LAST`（上一帧 direction / speech）。服务重启后缓存清空，不影响正确性。

## 9. 播报与读屏

曾出现两类故障：

- 模型或规则把实时结果写成固定套话，每隔几秒重复；
- 屏幕上的 `resultSpeech` 已更新，TTS / 读屏仍停在**第一次**结果。

原因：

1. 结果卡片同时带 `aria-live` 与冻住的 `aria-label`，每帧 `setData` 导致读屏反复念旧句；
2. 播报判定未比较 `speech` 文本，方向为「未确定」时 8 秒内不播新句；
3. TTS 始终覆盖同一个 `nextstep-tts.mp3`，后一次合成可能播到旧音频。

当前策略：

| 通道 | 行为 |
|---|---|
| 屏幕文字 `resultSpeech` | 每帧更新，方便核对，**不含** `aria-live` |
| 读屏旁白 `spokenLive` | 独立隐藏 live 节点，仅在真正要说时更新 |
| 应用内 TTS | 句子变化才合成；相同句子不循环 |
| TTS 文件 | `nextstep-tts-{序号}.mp3`，过期请求丢弃 |
| 震动 | 高风险长震，中风险短震 |

判定函数 `shouldSpeak`：比较压缩后的 speech（去空白与标点）。高风险从非高风险升上来时立即播。精确确认始终播本次。

用户可在设置中关闭应用内 TTS，只保留系统读屏，避免叠读。

## 10. 无障碍交互

- 摄像头对读屏隐藏（`aria-hidden`）；
- **主按钮与视觉布局保持原样**：开始/停止实时辅助、精确确认、重新播报、停止播报、设置、五项任务；
- 首次使用弹窗安全边界（`SAFETY_TEXT`）；
- 文案偏短、偏安全，强调停下确认，而不是指挥用户伸手抓取。

安全说明原文：

> 本软件只提供环境信息辅助，不能替代导盲杖、导盲犬、无障碍设施或人工协助。不能用于过马路决策，也不能保证通道绝对安全。距离只是粗估计。不确定时请停下，重新确认或寻求协助。

## 11. API 摘要

鉴权：请求头 `X-App-Token`，或 `Authorization: Bearer <口令>`。未配置 `APP_TOKEN` 时网关不强制校验（仅便于本机调试，生产必须配置）。

### 11.1 健康检查

```http
GET /health
```

返回网关状态与模型配置是否已加载。

### 11.2 可用模型

```http
GET /models
Header: X-App-Token: <业务口令>
```

返回 `default_profile` 与对外可见的 profile 列表（不含密钥）。

### 11.3 推理

```http
POST /infer
Content-Type: multipart/form-data
Header: X-App-Token: <业务口令>
```

| 字段 | 说明 |
|---|---|
| `image` | 必填，图片文件 |
| `question` | 用户问题 / 任务模板 |
| `mode` | `live` 或 `precise`，其它值按 `precise` |
| `model_profile` | 可选，默认 `primary` |
| `distance_band` | 可选，端侧粗距离带 |

成功时 `result` 为第 6 节 JSON；解析失败时 `status=unparsed` 并带回 `raw_answer`；调用失败时 `status=error`。实时丢帧为 HTTP 429。

### 11.4 TTS（可选）

```http
POST /tts
Content-Type: application/json
{"text": "注意前方有台阶。入口在右前方。"}
```

文本截断至 200 字。TTS 失败时前端仍可通过读屏节点播报。

## 12. 预留能力（当前未接线）

`services/fusion.py` 已实现纯函数：

- 方向相邻判定、跨侧冲突、从文本回填方位；
- `FusionConfig`：`none` / `parallel` / `conditional`；
- 风险只升不降、方向冲突则「未确定」。

桌面仓库 `model_profiles.json` 目前只有 `primary`（MiMo）与占位 `backup`，**没有 `verify` profile**。因此主路径不会并行调用第二模型。

若后续启用异构验证，建议：

| 模式 | 策略 |
|---|---|
| 精确确认 | 主模型与验证模型并行，字段级融合后再播报 |
| 实时辅助 | 主模型先返回；仅低置信 / 方向变化时后台验证，结果写入下一帧记忆 |
| 高风险帧 | 不等待验证，先播「停下确认」 |
| 方向冲突 | 不投票猜方向，降为「未确定」 |
| 价格/OCR | 两边不一致则不播具体数字 |

这与 v1.2 设计一致，但必须以当前 `model_profiles.json` 是否配置验证模型为准，避免文档超前于代码。

## 14. 质量与测试

后端单测覆盖（`tests/test_runner.py` 等）：

- JSON 围栏解析；
- 非法方向归为未确定，且不输出「不确定方向 / 重新拍摄」套话；
- 伪精确度量（米、步）清洗；
- 高风险前置「注意」；
- 实时 Prompt 长度与套话禁令；
- 粗距离带写入且不引入「米」。

已知限制：

- 二维语义方位，不是世界坐标；
- 粗距离带，不是 LiDAR；
- 实时依赖单帧视觉，无长期地图；
- 进程内 `LIVE_LAST` 不能跨实例共享；
- 当前桌面仓库主路径为单主模型。

可选后续：异构验证模型、Session 关键帧对照、独立 OCR、原生端深度、用户级鉴权。

## 15. 结论

v1.3 把系统定义为：

```text
小程序采集
+ 远程视觉理解
+ 结构化方位与风险
+ 安全清洗
+ 句子级播报（文案变了才说，相同不循环）
```

它解决的是「看懂画面」到「敢伸手、敢出门」之间缺的那一句行动提示，并守住不确定就降级、不替代辅助器具的边界。
