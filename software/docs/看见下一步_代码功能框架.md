## 1. 系统在做什么

视障或低视力使用者说一句话，或者什么都不说。系统看眼前这一帧，或者只回答这句话，然后用一句短话朗读。

代码里实际分成两条代理，共用同一个 FastAPI 进程，也共用同一套口令。它们不是两个操作系统进程。

| 代理 | 代码里的名字 | 看不看照片 | 干什么 |
|---|---|---|---|
| 视觉代理 | `understanding.agent = "vision"`，`kind` 为 `task` 或 `watch` | 看 | 空闲时描述眼前；有任务时找东西、指路、看价格、看障碍 |
| 聊天代理 | `understanding.agent = "chat"`，`kind` 为 `chat` | 不看 | 问好、天气、新闻、今天发生的事。天气和新闻强制联网 |

照片字节只进入视觉代理。聊天代理的 HTTP 请求里没有 `image_url`。

还有一条语音识别通道，把眼镜页录下的声音变成文字，然后再走上面两条代理之一。小程序默认不走这条通道，它用微信同声传译插件在手机上转写。

## 2. 谁在跑

### 2.1 云端网关

启动命令是 `python server.py`。`parse_args()` 默认 `--host 0.0.0.0`、`--port 8000`。`--mock` 时不连真实模型。

进程内有这些长期对象：

- `MiniCPMOAccessibilityRunner`：分类、闲聊、看图。
- `ASRHandler`：转写。
- `TaskMemoryStore`：这一趟主任务，默认库文件 `task_memory.sqlite`。
- `LongMemoryService` / `HighlightBook`：跨会话重点，默认库文件 `software/server/highlights.sqlite`。
- `INFER_LOCKS`、`ASR_LOCKS`：按「口令 + 会话」分的 `asyncio.Lock`。
- `LIVE_LAST`：上一帧的方向和句子，用来防抖。这三本字典只活在当前进程里，没有淘汰。

`uvicorn` 没有在代码里写 `--workers`。锁、上一帧、以及任务库的内存缓存都是单进程的。开多个 worker 之后，丢帧和「上一句方向」不再共用。

### 2.2 三个客户端

1. 眼镜网页 `GET /glasses/`，静态文件在 `software/server/static/glasses/`。电脑演示用笔记本摄像头。手机演示也可以打开同一页，用手机摄像头。
2. 微信小程序，页面只有 `pages/assist/assist` 和 `pages/settings/settings`。自己拍照，语音用微信插件。
3. Android 手机程序，本地端口 `8788`。WiFi 摄像头把 JPEG 送到手机，手机再调用云端 `/infer`。眼镜浏览器打开 `http://<手机热点网关>:8788/`，这一页只有说话和朗读，没有镜头。

`software/server/app.py` 是 Gradio。它不提供 `/glasses/`。环境变量没设 `APP_TOKEN` 时，它使用源码里的默认口令，并把口令写在页面说明里。正式口令不要靠这个入口分发。

## 4. 一条 `/infer` 怎么走完

客户端用 `multipart/form-data` 调用 `POST /infer`。

字段：

| 字段 | 必填 | 代码里的处理 |
|---|---|---|
| `image` | 是 | 先整段读入内存，再看大小。后缀只允许 `.jpg` `.jpeg` `.png` `.webp` |
| `question` | 否 | 默认「请判断当前是否安全，并告诉我目标在哪个方向。」空闲看画面时会被换成另一句，见第 7 节 |
| `mode` | 否 | 只认 `live` 和 `precise`，别的都当成 `precise` |
| `spoken_text` | 否 | 截到 120 字 |
| `session_id` | 否 | 不截断。空则用口令标识。这是主任务的键 |
| `user_id` | 否 | 截到 64 字。空则不写长期重点 |
| `client` | 否 | 截到 32 字。手机固定写 `phone` |
| `tof_mm` | 否 | 有值就收成远近档，覆盖 `distance_band` |
| `distance_band` | 否 | 一臂内 / 较近 / 较远 / 无法判断 |
| `model_profile` / `model` | 否 | 可临时指定视觉配置或模型名 |
| 头 `X-App-Token` 或 `Authorization: Bearer` | 看部署 | 见第 14 节 |

大小限制默认图片 5MB（`MAX_UPLOAD_BYTES`），语音 10MB（`MAX_ASR_BYTES`）。判断发生在 `read()` 之后。环境变量会盖过函数参数。

然后按下面的顺序处理。顺序不能颠倒着理解，因为后面的步骤吃前面的结果。

1. 校验口令。`APP_TOKEN` 为空时任何请求都通过，身份记成 `anonymous`。
2. 校验图片后缀和是否为空。
3. 取会话锁。锁已经被人拿着就返回 `429`，正文是「上一帧仍在识别中，已丢弃本帧」。判断和加锁不是同一步，两个请求有可能都看到锁是空的，然后一个排队而不是被丢掉。
4. 读出这个 `session_id` 上一次的主任务。超过 30 分钟的会话在 `get()` 时删掉。
5. 如果有 `spoken_text` 且不是在问以前，调用 `classify_utterance`。这是一次纯文字请求，超时 6 秒，最多 40 个 token。失败就当没分类，退回关键词。
6. `understand_speech` 得到 `kind`、`intent`、`target`、`summary`。
7. 决定这一帧是 `chat`、`task` 还是 `watch`。规则在第 5 节。
8. `revise_main_task` 决定主任务是 new / keep / refine / switch。`watch` 不读旧任务，避免把已经结束的寻找又写进提示词。
9. 选问题句和附加提示。只有 `task` 才把「主任务记忆」塞进视觉提示词。
10. 进入锁内部：
    - `chat`：不写临时文件，不看图。停一下或否定就回「先停一下，这个先不找。」问以前先留空，等后面补记忆。其他闲聊调用 `chat_reply`。
    - `task` 和 `watch`：图片写入临时文件，调用 `infer_image`，`finally` 里删除临时文件。
11. 把判定写回解析结果。`watch` 把 `main_task` 清空。`task` 再经过 `humanize_search_speech`，把找东西的句子收成「正在帮你找……在你哪一侧……」。
12. 有 `user_id` 时，用 `build_highlights` 生成重点并写入本机账本。问以前时先读本机，本机没有再考虑云端。
13. `live` 且是 `task` 或 `watch` 时，`stabilize_live_result` 用上一帧压住套话和来回跳的方向。
14. `object_found` 只在 `kind == task` 时判断。找到了就把这条主任务标成 `done` 并写入 sqlite。
15. 返回 JSON。找到之后，响应里的 `task.main_task` 是空字符串，避免客户端下一帧还显示「正在找」。

看图请求是同步的 `urllib.request.urlopen`，跑在异步路由里。视觉超时来自 profile，当前 primary 是 120 秒。这段时间会占住事件循环。

## 5. 这一帧算哪一种

```
有 spoken_text
  → understand_speech 的 kind（task 或 chat）
没有 spoken_text，但这个会话还有没完成的主任务
  → task
没有 spoken_text，mode 是 live 或 precise
  → watch
其他
  → chat
```

「没完成的主任务」四个条件都要成立：会话里有记录、`main_task` 非空、`done` 是假、`intent` 属于任务意图。

任务意图集合：

- `find_product` 找东西
- `guide_way` 指路
- `find_entrance` 找入口
- `find_cashier` 找收银台
- `read_price` 看价格
- `avoid_obstacle` 看障碍

问以前（`ask_past`）和先停下（`stop`）走聊天分支，不看图，也不把这句话写成新的寻找目标。

## 6. 用意是怎么判的

`understand_speech` 先信模型，模型没给出可用结果再用规则。

模型被要求只输出一行 JSON：

```json
{"kind":"task|chat","intent":"找东西|指路|看价格|看障碍|问以前|先停下|其他","target":"短目标或空","summary":"一句口语"}
```

提示词写明：找东西、指路、看价格、看障碍才是 task。问好、闲聊、天气、新闻、今天发生的事是 chat。指路是往哪边走、出入口或收银台在哪一侧，不是过马路。

规则层按这个顺序：

1. 模型说了具体任务意图，就用模型的。
2. 模型说 chat，或意图里有「其他」，就当闲聊。问以前和先停下仍保留。
3. 关键词：收银、入口、指路、价格、障碍、找/买/拿。
4. 命中天气、气温、下雨、新闻、大事、热点、头条、发生了什么、今天有什么、你好、谢谢、再见，就是闲聊。
5. 很短、又不像安全或问路的话，当成找商品。例如只说一个商品名。

`needs_live_info` 用同一组天气和新闻词。命中才强制联网。单独说「你好」不强制搜索。

## 7. 视觉代理

### 7.1 空闲看画面 `watch`

没有寻找任务时，问题被固定成：

「请看眼前这一帧。有危险先说注意。用一句短话说眼前有什么。不要说正在找什么。」

不附带主任务记忆。不调用 `humanize_search_speech`。不判断「找到了」。响应里：

- `understanding.kind = watch`
- `understanding.agent = vision`
- `understanding.label = 看眼前`
- `task.decision = watch`
- `task.main_task = ""`
- `task.intent = general_help`
- `sensors.camera = true`
- `sensors.tof = false`

眼镜页因此会继续上传下一帧。

### 7.2 有任务 `task`

问题来自 `build_question`。找商品时要求在当前照片里找那个目标，话术先提醒风险，再说方位，并要求能摸到的参照：

- 货架、柜子：手高这一层、再高一层或再矮一层，从使用者左手边数第几个。
- 桌子、台面、空白平面：靠近你这一侧或靠里，加上靠左、中间、靠右。不数第几个。
- 不说米、厘米、步数，不说伸手抓、直接前进、过马路。

`format_task_context` 把上次主任务、最近四句语音、本次判定、当前要找的东西写进提示词。提示词要求立刻在这一帧里找，不要只说「已经记下」。

方向只允许：左侧、左前方、正前方、右前方、右侧、未确定。

风险：`low` / `medium` / `high`。高风险时话术以「注意」开头。

`compose_find_speech` 在方向已知时写成「在你{方向}」。没看到就写成「还在帮你找」。

`sanitize_guidance` 会把「约、米、厘米、cm、步、度」这一类距离抹成「无法准确判断的距离」。英文 `m`、`mm`、毫米不在这组里，可能原样留下。`30度` 也会被抹掉。

### 7.3 实时防抖

`mode=live` 且是 `task` 或 `watch` 时调用 `stabilize_live_result`。它看上一帧的方向和句子，避免套话来回变，或两个相邻方向打架。精确模式 `precise` 不走这一步。

### 7.4 模型配置

`model_profiles.json`：

| 名字 | 现在的用途 | 缺密钥时 |
|---|---|---|
| `primary` | 看图，也是分类和闲聊的退路。模型 `mimo-v2.5`，地址 `https://api.xiaomimimo.com/v1`，思考关闭，超时 120 秒，最多 1024 token | 看图失败 |
| `chat` | 如果配了自己的密钥和真实地址，闲聊走这里 | 示例地址或没密钥时，闲聊改用 primary，仍然不传图片 |
| `backup` | 备用视觉。主路径不调用 | 占位 |

环境变量可以盖过 JSON：`MODEL_API_BASE_URL`、`MODEL_NAME`、`MODEL_API_KEY`，以及 `CHAT_*`、`BACKUP_*`。

## 8. 聊天代理

`chat_reply` 在 mock 时固定回「我在听。你要找东西，或者问往哪边走，直接说就行。」

真实调用 `ModelGateway.complete_chat`：

- 只发文字。
- 超时 20 秒，最多 180 token。
- 系统要求：不看画面，不找东西，不指路；最多两句；不念网址；不说米和步；查不到就说没查到。
- 提示词里带上当天日期。
- `needs_live_info` 为真时附带工具：

```json
{"type":"web_search","max_keyword":2,"force_search":true,"limit":3}
```

`tool_choice` 是 `auto`，并关闭思考。这是小米 MiMo 的联网搜索插件。账号要在控制台开通，否则这次闲聊会失败，用户听到「我没查到最新的消息。」

回答再经 `_speakable_chat`：去掉网址、去掉「正在帮你找……」、只留前两句、最多 72 字。这里不用距离清洗，避免把「24度」抹掉。

聊天响应：

- `sensors.camera = false`，`sensors.tof = false`
- 不把这句话写成主任务
- 已经存在的寻找任务也不会因为一句天气被改掉

眼镜页下一帧如果没有新的语音，又会回到 `watch` 或未完成的 `task`。所以问完天气，看画面会继续。

手机还没有把地址、天气、时间传上来。聊天代理现在只能靠联网搜索，用户没说城市时模型自己选一个结果。后面若手机带上这三项，应该先用手机的，搜索只做退路。这个接口字段现在还没有。

## 9. 这一趟主任务

存在 `TaskMemory`：

| 字段 | 含义 |
|---|---|
| `session_id` | 客户端给的会话 |
| `intent` | 上面的任务意图，缺省 `general_help` |
| `target` | 短目标，例如「可乐」 |
| `main_task` | 给人和模型看的整句任务 |
| `question` | 下一帧看图时用的问题 |
| `utterances` | 最近最多 8 句 |
| `updated_at` | 最后写入时间 |
| `done` | 找到之后为真 |

`TTL_SECONDS = 30 * 60`。过期在读取时清理，没有后台定时器。

`revise_main_task` 在没有新语音时：有旧任务就 `keep`。有新语音时：

- 没有旧任务：`new`
- 出现「改成 / 换成 / 不找了」或意图变了：`switch`
- 出现左右、远近、第几排，或意图相同：`refine`，原目标还在，补充句拼到主任务后面
- 其他：`keep`

`looks_like_product_request` 会把没有明显意图的短句收成找东西。天气和新闻词在 `understand_speech` 里先被排除，不会走到这里。

保存只发生在 `kind == task` 且有话或有主任务时。`watch` 不写库，所以空闲看画面不会把「眼前有桌子」记成新任务，也不会把已经 `done` 的任务重新打开。

找到时：

```
remembered.done = True
task.decision = done
task.found = true
task.main_task = ""
task.reason = 任务已经完成
sensors.camera = true
sensors.tof = false
```

摄像头仍开着，因为空闲识别要继续。测距口关掉，因为寻找结束了。

## 10. 什么叫找到了

`object_found` 只接受 `find_product`、`find_entrance`、`find_cashier`。

全部满足才返回真：

- 方向是五档之一，不是「未确定」
- 置信度是 `medium` 或 `high`
- 句子里没有「还在帮你找」「没看到」「没有看到」「继续观察」
- 锚点是货架、柜子、桌子、台面、平面之一，或者句子里有「在你」

`guide_way`、`read_price`、`avoid_obstacle` 不会被这个函数判成完成。指路说完一个方向，任务仍可能留在这 30 分钟里。

因为找东西话术自己会写「在你{方向}」，方向一旦确定且置信度够，任务就会结束。锚点不是唯一条件。

## 11. 测距

`band_from_tof_mm`：

| 毫米 | 说法 |
|---|---|
| 非数字、小于等于 0、NaN | 无法判断 |
| ≤ 800 | 一臂内 |
| ≤ 2000 | 较近 |
| 更大 | 较远 |

毫米数字不会进朗读。没有读数就是无法判断。软件里没有读硬件 ToF 的代码，只接收客户端传来的 `tof_mm`。

`sensors_for` 仍在：`task` 要摄像头和测距，`chat` 不要。`/infer` 现在自己组传感器字段，不完全调用这个函数。实际返回是：

- 视觉且没有说「先停下」：`camera true`
- 只有还在进行的 `task` 且还没找到：`tof true`
- 聊天或先停下：两个都是 false

## 12. 一天内的重点

这是长期记忆，和 30 分钟主任务不是同一张表。

### 12.1 本机

`HighlightBook` 默认写入 `software/server/highlights.sqlite`，表 `highlights(user_id, payload)`。`HIGHLIGHT_DB_PATH=memory` 时只放进程内存，重启就没了。

`NOTE_TTL_SECONDS = 24 * 60 * 60`。从这条重点最后一次被说到的 `updated_at` 起算，超过 24 小时，下次读取时删掉。同一句再说一次会增加 `uses` 并刷新时间。最多留 20 条。

会记的短句，由 `build_highlights` 决定：

| 用户说的 | 记下 |
|---|---|
| 嗯、啊、看到了吗、到了吗 | 不记 |
| 不是这个、不要了、别找 | `纠正：先不要按旧说法找{旧目标}` |
| 记住、帮我记、别忘了 | `记住：{后面的话}` |
| 新的或换掉的寻找，且有明确目标 | `常找{目标}` |
| 我喜欢、我习惯、以后叫、别名 | 原话，最多 40 字 |
| 其他，包括天气和普通闲聊 | 不记 |

不存照片，不存整段画面描述。

分组：`kept`（记住）、`finds`（常找）、`corrections`（纠正）。

问「上次 / 以前 / 我常找 / 找的是什么」时，`is_recall` 为真。服务先 `list_highlights`。本机有内容就用本机，不再打云。读出来后改成口语：`常找可乐` 说成「你常找的是可乐。」没有就说「我还没记下你之前说的重点。」

眼镜页 `localStorage` 键 `memoryHighlights` 也按 24 小时过滤，最多 20 条。这是浏览器里的一份副本。重启服务器后还在的是 sqlite。

`DELETE /highlights?user_id=` 清空这个用户的本机重点。

### 12.2 记忆张量云端

`MEMOS_API_KEY` 为空，或是 `replace-with` 开头，云端关闭。识别照常进行。

密钥有值且装了 `memos` 包时，`LongMemoryService.enabled = true`，客户端指向 `MEMOS_BASE_URL`，默认 `https://memos.memtensor.cn/api/openmem/v1`。搜索超时 0.3 秒，超时就当没搜到。缓存 10 分钟。

`schedule_write` 可以把重点发给云端，但 `server.py` 没有调用它。所以即使得了密钥，当前请求路径也不会把重点上传。云端搜索只在本机账本是空的、而且用户在问以前时才可能发生。

包没装上时，`build_long_memory` 会返回一个不带本机账本的关闭服务。这和「密钥为空仍写 sqlite」不是同一条路径。

## 13. 语音

### 13.1 眼镜页怎么听

点一下「点一下说话」开始录，再点一下结束。按住超过 500 毫秒再松开，也是结束。录音用 `MediaRecorder`，收成 16 kHz 单声道 WAV，`POST /asr`。浏览器自带的 `SpeechRecognition` 不是主路径。

录音期间停掉 2.5 秒看画面的定时器，说完再开。

转写失败或太短：说「没听清，请再说一次。」口令错：说「口令不对。」

### 13.2 `/asr`

未配置时 `501`。配置规则：

1. `--mock`：固定返回「请帮我找目标商品，先提醒风险，再给出方向。」
2. 设了 `ASR_API_BASE_URL`：走 OpenAI 兼容的 `/audio/transcriptions`，模型默认 `whisper-1`。
3. 没设 ASR 地址，但 `MODEL_API_BASE_URL` 含 `xiaomimimo.com` 且有 `MODEL_API_KEY`：走 `mimo-v2.5-asr`，把音频放进 chat completions 的 `input_audio`。
4. 否则关闭。

和看图一样，先读完全部字节再限制 10MB。同一会话上一句还在识别就 `429`。

### 13.3 `/tts`

正文 JSON `{"text": "..."}`，最多取 200 字。用 `edge-tts` 的 `zh-CN-XiaoxiaoNeural`，返回音频字节。没安装这个包时 `501`。眼镜页失败后退回 `speechSynthesis`。

眼镜页上 `#speech` 是 `aria-live="assertive"`，同时 `speak()` 会再播一遍。读屏开着时，同一句可能被念两次。

### 13.4 小程序

`app.json` 声明插件 `WechatSI` 0.3.9。录音权限说明写在 `scope.record`。转写在手机里完成，不经过 `/asr`，除非某条代码路径显式上传。

## 14. 口令、健康检查和模型列表

`verify_token`：配置了 `APP_TOKEN` 时，头里的值和它必须相等，用的是普通 `!=`，不是常量时间比较。没配置就全部放过。

`GET /local-app-token`：调用方 IP 是本机或私网（10/8、172.16/12、192.168/16，含 IPv4 映射）时，返回 `{"token": ...}`。公网 IP 得到 404。CORS 是 `*`。同一局域网里的网页可以取到口令再调用 `/infer`。

`GET /health` 不需要口令。进程活着就是 `status: ok`，不探测模型是否真的能通。里面有各 profile 的地址、模型名、`api_key_configured` 布尔值，没有密钥本身，但有 `last_error`。

`GET /models` 需要口令，返回公开 profile。

`GET /glasses` 307 到 `/glasses/`。静态目录由 FastAPI `StaticFiles` 挂出。

FastAPI 默认还有 `/docs` 和 `/openapi.json`，代码没有关掉。

## 15. 眼镜页状态机

文件：`index.html`、`app.js`、`style.css`。脚本地址带 `?v=11`，用来避开旧缓存。

常量：

- `LIVE_MS = 2500`：看画面的间隔。
- `SPEAK_GAP_MS = 4000`：定义了，播报去重主要靠句子和方向，不靠这个间隔硬挡每一帧。
- 默认问题：判断是否安全并说方向。空闲帧到了服务器会被换成第 7.1 节那句。

本地存储：

| 键 | 内容 |
|---|---|
| `glassesApi` | 服务器地址，空则用当前页面的源 |
| `glassesToken` | 口令 |
| `glassesUserId` | `u` + 时间 + 随机，不是密码学随机 |
| `glassesSessionId` | 会话 |
| `memoryHighlights` | 24 小时内的重点副本 |

地址栏 `?token=` 和 `?api=` 会写入上面的存储。`?task=` 最多 80 字，页面打开并等到画面有宽度后，用新的 `task{时间}` 会话做一次精确识别，然后如果摄像头还开着就进入 2.5 秒循环。

打开顺序：取本机口令、拉重点、开摄像头、开麦克风、如果有 `?task=` 就下发。

摄像头使用 `facingMode: environment`，理想 1280×720。麦克风单独一条音轨。页面隐藏时停定时器，重新可见且没在录音就再开。没有「摘下眼镜」的传感器判断。

`captureAndInfer`：

- 没在运行，或正在录音，直接返回。
- 上一帧还没回来，且这次不是「带着新语音的精确模式」，直接返回。所以 live 会丢帧，不排队。
- 视频还没有宽度，返回。
- 精确模式质量 0.86，实时 0.7。画面先缩到最长边不超过 960。
- `429` 不朗读。
- 实时模式的网络失败不朗读。精确模式会把错误说出来。

`handlePayload`：

- `task.found` 或 `decision == done`：记下「已经找到：{目标}」，清空当前任务，问题恢复默认。状态写成「已经找到」，这句话说一次。
- 定时拉重点时，如果没有新任务，这一行保持「已经找到」，不会被刷回「还没有」。
- 新的任务句子到来时清掉「已经找到」。
- 没在找东西：状态是「正在看」。
- 相同句子、方向没变、或方向未确定，实时模式不再念。第一句、风险刚变成高、方向变了，会念。
- 精确模式和「找到了」总会尝试念，除非和上一句完全一样。

点一下说话的实现在 `bindHold` / `beginTalk` / `endTalk` / `finishTalk`。短按进入 `tapToTalk`，再按结束。长按松开结束。`holdToken` 用来避免手指已经松开、异步开麦还没回来时又开始录。

## 16. 微信小程序

`pages/assist/assist.js` 自己循环：用户打开「实时辅助」后大约按间隔拍照调用 `/infer`。以前在 `sensors.camera === false` 时直接不拍。这段判断已经去掉，所以实时辅助打开期间会继续传帧，不再只在找东西时才识别。

精确确认、语音任务、失败提示仍在这个页面里。语音走微信插件。朗读走 `utils/tts.js`。深度估计在 `utils/depth.js`，把结果当成 `distanceBand` 传上去，不是 ToF 毫米。

设置页保存 API 地址和口令。存储键在 `utils/config.js`。

小程序没有把系统定位、天气和时钟发给网关。

## 17. 手机中转

`software/android`，端口 8788。

摄像头 `POST /frame`，正文是 JPEG。`hub_policy.frame_action` 和 Kotlin `FrameRules` 使用同一套规则：

| 条件 | 动作 |
|---|---|
| 上一帧还在等网关 | `drop`，这一帧丢掉，不排队 |
| 有新的语音，或上次响应要求摄像头继续开 | `forward`，立刻 `/infer` |
| 其他 | `store`，只留下最新一帧，不上传 |

转发时 `client=phone`，`user_id=phone`，`session_id` 由手机保持。问题句目前写死为默认的安全与方向问题。`spoken_text` 来自眼镜页提交到手机的那句话。

响应里的 `sensors.camera` 写回 `cameraOn`。任务进行中或空闲看画面时，这个值是 true，手机会继续转发。聊天那一帧是 false；如果同时没有新语音，下一帧会被存住而不上传，直到再有语音或某一帧又把 camera 设回 true。

`GET /speech` 给眼镜播报页。找到之后 `decision` 为 `done`，播报页把「正在找」改成「已经找到」，并在出现新目标前保持。

默认网关地址写在手机设置里，工程里的示例是 `https://watchapi.divesee.com`。本机调试要改成电脑的局域网地址。


找到之后，`result.main_task` 仍可能带目标，供这句话组织播报；`task.main_task` 被清空，客户端用后者决定还找不找。

错误：

| 码 | 何时 |
|---|---|
| 400 | 后缀不对或图片为空 |
| 401 | 口令不对 |
| 413 | 图片或语音超过上限 |
| 429 | 上一帧或上一句还在处理 |
| 501 | ASR 或 TTS 没装好 |
| 502 | 转写上游失败 |
| 503 | 合成失败 |

看图上游失败时，多数情况仍是 HTTP 200，`status` 为 `error`，`error` 里有说明。眼镜页实时模式不会把这个失败念出来。

## 20. 客户端和服务器各自守什么

| 行为 | 服务器 | 眼镜页 | 小程序 | 手机 Hub |
|---|---|---|---|---|
| 空闲也看 | `watch` 看图 | 摄像头打开就每 2.5 秒一帧 | 实时辅助开着就继续拍 | `camera=true` 就转发 |
| 找到就结束任务 | `done`，清空 `task.main_task` | 显示「已经找到」，不再说正在找 | 要看该页有没有读 `found` | 播报页看 `decision==done` |
| 看画面继续 | `camera` 仍为 true | 定时器不停 | 不再因为 camera false 停拍 | 会继续转发 |
| 天气新闻 | 聊天代理联网，不看图 | 转写后走 `/infer` | 插件转写后走 `/infer` | 把这句话和最新图一起送出，服务器仍不看这张图 |
| 一天记忆 | sqlite 24 小时 | localStorage 24 小时 | 拉 `/highlights` | `user_id` 固定为 `phone`，重点记在这个 id 下 |
| 30 分钟任务 | sqlite | `session_id` | `session_id` | 手机自己的 `session_id` |

## 22. 现在没有的东西

这些在文档或对话里出现过，但当前请求路径里没有：

- 第二个视觉模型并行或条件复核。函数在 `fusion.py`，`/infer` 不调用。
- 摘下眼镜就停。只有页面隐藏才停定时器。
- 手机把定位、系统天气、系统时间传给聊天代理。
- `schedule_write` 把重点写入记忆张量。密钥为空时整个云端关闭。
- 像素级图片校验、EXIF 剥离、按 Content-Length 在读正文前截断。
- 多进程共享的丢帧锁。
- 常量时间口令比较。空口令是放行。
- 指路、看价格、看障碍的「任务完成」判断。只有找东西、找入口、找收银台会 `object_found`。
