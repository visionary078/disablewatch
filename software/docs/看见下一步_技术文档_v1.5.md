## 1. 产品定位

「看见下一步」面向盲人与低视力用户，把手机摄像头画面转成**可执行的下一步**，而不是普通看图问答。

起点来自真实使用失败：货架前把画面交给通用视觉对话模型，得到的是「画面里有货架」，而不是「第几排、在哪一侧、要不要先停下」。另一类用户社恐、不愿开口求助，越不出门越不敢出门。因此产品做成**微信小程序**：零额外硬件、扫码即用、自己就能完成选购与出门前的一小步。

视障用户往往无法准确点选任务按钮或编辑文本框。语音通道让用户用口语说出「帮我找可乐」「收银台在哪」。系统把这句话变成当前识别问题，对着镜头给出方位与风险，并记住主任务：下一句如果是「再往左边一点」就继续找可乐；如果是「现在去收银台」就切换目的。

系统输出：

```text
风险提示
+ 参照物 / 场景
+ 二维方位（左 / 左前 / 正前 / 右前 / 右）
+ 粗接近度与可选距离带
+ 当前主任务（可跨句保持或切换）
+ 一句适合播报的 speech
```

明确不承诺：

- 替代导盲杖、导盲犬或人工协助；
- 单帧证明通道绝对安全；
- 米、厘米、步数、角度等伪精确度量；
- 过马路决策；
- 完整三维导航或 SLAM。

## 2. 设计原则

1. **行动优先，描述其次。** 输出必须能指导「停下 / 转向 / 靠近确认」。
2. **不确定就降级。** 非法方向、看不清目标时归为「未确定」，用画面里真实看到的内容造句。
3. **危险只升不降。** 台阶、车辆、玻璃门、地面障碍优先于找目标。
4. **密钥不出端。** 小程序只访问自有网关，只持业务口令 `APP_TOKEN`。
5. **语音转写在端侧完成。** 长按录音由 WechatSI 转成文本后再上传，不把模型密钥放进小程序。
6. **主任务可跨句。** 新语音先与历史主任务比对，再决定继续、补充还是切换。
7. **相同句子不循环。** 实时模式只在文案变化、风险升高，或未确定场景满 4 秒后才再播。

## 4. 系统架构

```text
微信小程序「爱总会看见」
  ├─ 后置摄像头
  ├─ 实时约 2.5 秒一帧（上一帧未完成则丢弃）
  ├─ 精确确认：高质量单帧
  ├─ 按住说话：WechatSI 录音 + 转写
  ├─ 可选端侧粗深度带
  ├─ 屏幕文字 / 读屏旁白 / 可选 TTS / 风险震动
        │ HTTPS + X-App-Token
        ▼
FastAPI 网关
  ├─ 鉴权、上传限制、识别锁
  ├─ 主任务记忆（内存 + SQLite）
  ├─ 新语音 → keep / refine / switch / new
  ├─ Prompt 注入 [主任务记忆]
  ├─ 远程视觉模型 + JSON 清洗
  ├─ 实时 stabilize_live_result
  └─ 可选 /tts、备用 /asr
        │
        ├─ 视觉：小米 MiMo mimo-v2.5
        └─ 语音：微信同声传译 WechatSI 0.3.9
```

视觉数据流：

```text
拍照 → 粗深度带（可选）→ POST /infer
     （question + session_id + 可选 spoken_text）
     → revise_main_task
     → Prompt + 图像 → 模型 JSON
     → normalize_result → apply_distance_band
     → 实时则 stabilize_live_result
     → 写回 task_memory
     → 屏幕 / 读屏 / TTS
```

语音需求数据流：

```text
按下「按住说话」
  → 申请麦克风
  → WechatSI getRecordRecognitionManager.start
松开
  → manager.stop → 得到中文文本
  → 拍当前画面
  → POST /infer（spoken_text + session_id + image, mode=precise）
  → 判定主任务
  → 视觉模型按当前主任务回答
  → 播报（切换时先说「主任务已改为…」）
```

## 5. 运行逻辑

### 5.1 任务模板

| 任务 | intent | 问题要点 |
|---|---|---|
| 找入口 | `find_entrance` | 入口方向，先提醒风险 |
| 找商品 | `find_product` | 目标商品方向，先提醒风险 |
| 识别价格 | `read_price` | 看得见的名称与价格，看不清不猜 |
| 找收银台 | `find_cashier` | 收银台方向，先提醒通道障碍 |
| 障碍提醒 | `avoid_obstacle` | 当前是否安全，目标在哪一侧 |

### 5.2 前端主路径

1. 摄像头就绪后展示安全说明（首次），默认可进入实时辅助。
2. **实时辅助**：约 2.5 秒一帧；上一帧未完成则丢弃。
3. **精确确认**：高质量单帧，强制播报。
4. **按住说话**：`catchtouchstart` 开始、`touchend / touchcancel` 结束；录音期间暂停实时辅助。
5. 按住不足约 400ms 视为无效，提示再按一次。
6. HTTP 429 前端静默丢帧。

### 5.3 后端 `/infer`

表单：`image`、`question`、`mode`、`model_profile`、`distance_band`、`session_id`、`spoken_text`。

处理：鉴权 → 校验图片 → 识别锁 → 读取该 `session_id` 的主任务 → `revise_main_task` → 组 Prompt（含 `[主任务记忆]`）→ 调模型 → 清洗 → 写回 SQLite → 返回 `result` 与 `task`。

无新语音时，仍把已有主任务注入 Prompt，使实时巡视继续服务刚才语音定下的目标。有新语音时，用判定后的 `revision.question` 作为本次用户问题。

## 7. Prompt 与安全清洗

系统 Prompt：中文、先危险再方位、方向只用六值枚举、不输出精确度量、不说「可以直接前进」、不能替代辅助器具。

实时模式：`speech` 一句、不超过 30 字；禁止套话；看不清时用画面真实物体造句。

含 `[主任务记忆]` 时：

- 按「当前主任务」回答，不要擅自改回已切换掉的旧目标；
- `keep` / `refine` 先服务原主任务，再顺带回答本次追问；
- `intent` 必须对应当前主任务。

## 8. 实时结果稳定与播报

`stabilize_live_result` 只作用于 live：套话改写成场景；未确定时可沿用上一合法方向；新的有效句子必须采用。

`shouldSpeak`：

1. 压缩后的 speech 变了 → 立即播；
2. 风险升到高 → 立即播；
3. 精确确认 / 语音确认 → 始终播；
4. 仍是「未确定」或「继续观察」→ 满 **4 秒**才允许再提醒（`SPEAK_GAP_MS = 4000`）；
5. 其它相同句子不循环。

屏幕 `resultSpeech` 每帧更新但不带 `aria-live`；读屏走隐藏 `spokenLive`；TTS 文件名为 `nextstep-tts-{序号}.mp3`。

## 9. 长按语音（WechatSI 0.3.9）

### 9.1 插件

`app.json`：

```json
"plugins": {
  "WechatSI": {
    "version": "0.3.9",
    "provider": "wx069ba97219f66d99"
  }
}
```

必须先在微信公众平台为小程序添加该插件，否则无法编译或运行时 `requirePlugin("WechatSI")` 失败。

麦克风权限：`scope.record`。

### 9.2 为什么是长按

v1.4 的点按开关会先播提示音再开麦，用户松开时录音往往还没开始，表现为「假按钮」。v1.5 按下立即 `manager.start({ duration: 60000, lang: "zh_CN" })`，松开 `manager.stop()`，在 `onStop` 取 `result` 文本。

交互控件使用 `view` + `catchtouchstart / catchtouchend / catchtouchcancel`，避免 `scroll-view` 或 `button` 吞掉手势。

### 9.3 发给模型

转写成功后：

1. 界面显示「听到：…」；
2. 拍摄当前帧；
3. `POST /infer`，`mode=precise`，带上 `spoken_text` 与 `session_id`；
4. 模型按判定后的主任务看图回答。

备用通道：`plugin.translateVoice`（对已有音频文件）以及服务器 `POST /asr`（需配置 `ASR_API_BASE_URL`）。主路径不依赖服务器 ASR。

## 10. 主任务上下文库

实现：`services/task_memory.py`。

存储：进程内字典 + SQLite 表 `task_memory(session_id, payload_json, updated_at)`。文件由 `TASK_DB_PATH` 指定，默认 `task_memory.sqlite`。会话 TTL 30 分钟，最近 8 句语音。

小程序用本地 `sessionId`（首次生成后写入 Storage）随每次 `/infer` 上传。

### 10.1 判定

`revise_main_task(previous, spoken_text)`：

| 判定 | 条件 | 随后怎么答 |
|---|---|---|
| `new` | 尚无主任务 | 用本次语音建立主任务并回答 |
| `keep` | 新语音未改目的 | 继续原主任务，把本句当作追问 |
| `refine` | 「再往左」「不是这个」等 | 同一主任务，合并补充后回答 |
| `switch` | 换成收银台、入口等新意图，或「现在去…」 | 覆盖主任务，按新目的回答 |

意图关键词示例：收银/结账 → `find_cashier`；入口/大门 → `find_entrance`；价格/多少钱 → `read_price`；障碍/台阶 → `avoid_obstacle`；找/买 → `find_product`。

### 10.2 写回与播报

推理成功后把判定结果写入库，并在 JSON 中返回 `task_decision`、`main_task`。前端结果区显示「主任务：…」。若为 `switch` / `new` / `refine`，播报前加一句「主任务已改为… / 已记下… / 继续…」。

## 11. 无障碍交互

保留：开始/停止实时辅助、精确确认、重新播报、停止播报、设置、五项任务。语音键文案为「按住说话 / 松开结束」。

摄像头 `aria-hidden`。可关闭应用内 TTS，避免与系统读屏叠读。首次使用弹窗安全边界。

> 本软件只提供环境信息辅助，不能替代导盲杖、导盲犬、无障碍设施或人工协助。不能用于过马路决策，也不能保证通道绝对安全。距离只是粗估计。不确定时请停下，重新确认或寻求协助。

## 12. API 摘要

鉴权：`X-App-Token` 或 `Authorization: Bearer`。生产必须配置 `APP_TOKEN`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | `status`、`model_gateway`、`asr_enabled` |
| GET | `/models` | 需口令，返回 profile 列表 |
| POST | `/infer` | 图片推理；可带 `session_id`、`spoken_text` |
| POST | `/tts` | 可选语音合成 |
| POST | `/asr` | 备用服务器转写（主路径不使用） |

`/infer` 实时丢帧为 HTTP 429。成功时除 `result` 外返回 `task`。

## 16. 结论

v1.5 把系统定义为：

```text
长按语音（WechatSI 转写）
+ 主任务上下文库（keep / refine / switch）
+ 摄像头画面
+ 远程视觉理解
+ 结构化方位与风险
+ 安全清洗
+ 句子级播报（变了才说；未确定最短 4 秒再提醒）
```

它补上「说不出任务」和「下一句还记不记得刚才要找什么」两环，并守住不确定就降级、不替代辅助器具的边界。
