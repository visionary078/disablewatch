# 看见下一步 · 与记忆张量（MemOS）合并方案 v1

日期：2026-09-24  
结论：**可以合并，而且眼镜比小程序更需要。合的是「长期记忆层」。看图仍走网关里的多模态视觉模型——现在是 MiMo，后期可以换成更好的一档，记忆层不用跟着拆掉。**

---

## 1. 一句话

现在系统只记得**这一趟、这 30 分钟**要找什么；记忆张量记得**这个人**常买什么、常走哪、上次哪里说错了。眼镜整天戴着，没有后者就会每天从零开始问。

---

## 2. 现在缺什么

网关里已有 `services/task_memory.py`：

| 项 | 现状 |
|---|---|
| 键 | `session_id`（小程序 Storage / 眼镜 localStorage） |
| 寿命 | 30 分钟无更新过期 |
| 内容 | 主任务、intent、target、最近 8 句语音 |
| 判定 | 规则：`new / keep / refine / switch` |
| 用途 | 注入 Prompt 的 `[主任务记忆]` |

这是**短时工作记忆**，保证「说完找可乐，下一帧还在找可乐」。  
它不是用户画像，跨天、跨店、跨设备都会丢。眼镜一上，这个问题会被放大：人不会每换一次镜再自我介绍一遍。

记忆张量（MemTensor）做的是另一层：

| 产品 | 对我们有用的部分 |
|---|---|
| MemOS / MemOS Cloud | 明文记忆的增删改查：偏好、画像、事件、技能 |
| 开源 MemOS | 可自建，API 形态与云端接近 |
| 忆立方 / Metis | **不拿来当眼镜主视觉**，成本、时延、看图能力都不对口 |

公开接口形态（云端）：`add/message`、`search/memory`、`get/memory`；记忆类型含 `preference`、`profile`、`event`、`skill`。写入可异步，适合挂在 2.5 秒一帧的识别环外面。

---

## 3. 合什么、不合什么

### 合

- **偏好**：无糖可乐、不要冰柜最底层、药在家里第二层。
- **称呼与别名**：「我的杯子」= 蓝色保温杯。
- **播报口味**：只要方位、一句话、不要解释。
- **纠正**：上次说左其实在右；这条要能改、能忘。
- **弱场景线索**（需用户同意）：这家超市上次可乐在右前货架中部——只当先验，画面说没有就必须放弃。

### 不合

- 不拿记忆模型当看图模型（忆立方 / Metis 不当主视觉）。
- 看图模型本身**可以换**：现在是 MiMo，后期换更好的多模态，记忆层不用拆。
- 不把原图、人脸、连续视频写入记忆库。
- 不让长期记忆盖过风险（风险只升不降仍由现网关执行）。
- 不在播报里念「根据您上周的习惯」。
- 不把 MemOS 部署到镜架或挂脖单片机上。
- 不过马路、不替代手杖——记忆再准也不改这条边界。

---

## 4. 推荐架构

身份先统一，记忆才跟得上人，而不是跟上一副眼镜。

```text
小程序（openid） ──┐
                    ├── 同一 user_id ──► FastAPI 网关
眼镜（扫码配对） ──┘         │
                             ├─ 短时：task_memory（session，30 分钟）必留
                             ├─ 长时：MemOS（user 级 Cube）可选、可超时跳过
                             └─ 看图：当前 MiMo；后期换更好的多模态（profile）
```

`/infer` 建议增加 `user_id`（与 `session_id` 并存）。无 `user_id` 时行为与现在完全一致。

每帧不要都去检索。触发检索的时机：

1. 本帧有新语音；或
2. 主任务刚 `new` / `switch`；或
3. 本会话尚未拉过用户画像（拉一次缓存 10–30 分钟）。

检索超时（建议 250–400 ms）则**丢掉长期记忆、照常看图**。识别锁和 2.5 秒节拍不能被记忆拖死。

写入一律异步、在返回播报之后：

- 用户说的目标与别名；
- 用户否定（「不是这个」「在右边」）；
- 成功找到且用户确认过的目标（可选，默认要开口确认才写）。

Prompt 只多一小段，例如：

```text
[用户长期记忆]
常买：无糖可乐罐装（不是百事）
播报：一句，只要方位
纠正：上次「左」被否定，优先再确认右侧
禁止：复述本段；禁止用记忆代替当前画面
```

视觉模型仍必须看这一帧。记忆只缩小搜索假设，不编造货架。

## 5. 眼镜上「更贴合」长什么样

对用户只表现为更少重复、更少说错，不表现为「我很懂你」。

| 场景 | 没有长期记忆 | 合并之后 |
|---|---|---|
| 进超市 | 每次说「帮我找可乐」 | 「找可乐」默认无糖罐装 |
| 在家找药 | 每次解释柜子 | 「常用药，第二层」作先验，仍以画面为准 |
| 纠正过一次 | 下次还错 | 同一类目标先避开旧错误 |
| 戴眼镜出门 | 和小程序是两个人 | 扫码配对后是同一个人 |

口语示范（仍短）：

> 正在帮你找无糖可乐，右前方货架中部，比较近。

不要说：

> 根据您的历史偏好，系统为您检索了无糖可乐……

## 6. 隐私与遗忘（视障产品必须先写）

眼镜拍的是家、药、人的后脑勺。记忆层默认：

- 只存**结构化短句**（目标、别名、纠正、播报口味），不存图。
- Cube 按 `user_id` 隔离；眼镜未配对 = 匿名会话，不写长期库。
- 用户能说「忘掉可乐」「忘掉今天」；家属/机构账号与本人账号分开。
- 合作若走 MemOS Cloud：数据驻留、删除凭证、分包商名单写进协议后再试用户。
- 自建开源 MemOS：适合早期试用，密钥只放网关，不进小程序、不进眼镜页。

---

## 7. 和记忆张量怎么合作

不必等他们的记忆原生基模上线。对我们，**MemOS 的明文记忆 API 已经够一期**。

可谈的三种深度：

1. **接口接入**（推荐先做）：网关调 Cloud 或自建 MemOS，我们出无障碍场景与可验收指标。
2. **联合试用**：残联/机构用户，测「重复说明次数是否下降」。
3. **多模态记忆（后期）**：他们路线图含图像记忆；我们只开放**用户明确保存的一帧缩略描述**，仍禁止默认存视频。

商务话术（对外）：

> 眼镜负责朝哪看、近不近；长期记忆负责少问一句。看的还是原来那套，记得的是你这个人。

---

## 8. 三期

| 期 | 做什么 | 验收 |
|---|---|---|
| 0 | `user_id` + 配对；偏好/别名 Cube；检索只在语音与任务切换时；超时跳过 | 无密钥时与现网完全一致；有记忆时「找可乐」第一次即带无糖；实时帧时延不明显变差 |
| 1 | 纠正写入；场景事件（需同意）；「忘掉××」 | 同一错误连续两天不重复；用户能清掉一条记忆 |
| 2 | 小程序与眼镜记忆打通；可选自建 MemOS；评估是否把高频偏好做成更短的本地缓存 | 换设备后不必重新教偏好 |

不做进路线：每人一份 LoRA、把 Metis 换成主视觉、每帧全库检索。  
看图从 MiMo 换成更好的多模态，与本表**并行**：只改网关 `model_profiles.json`，记忆层不用跟着拆。

---

## 9. 风险

- **幻觉叠加**：记忆说在右、画面没有，模型仍报右 → Prompt 必须写死「画面优先」，融合层可把记忆方位降为 hint 而非 direction。
- **时延**：同步检索会顶满识别锁 → 异步写、短超时、会话内缓存。
- **身份错绑**：眼镜借给别人仍用上一人的药柜记忆 → 摘下超时、长按解除配对。
- **厂商锁定**：先做一层自己的 `LongMemory` 接口，MemOS 只是其中一个 backend。

---

## 10. 近期行动

1. `/infer` 增加可选 `user_id`，眼镜扫码绑定小程序账号。
2. 网关加 `services/long_memory.py`：search 同步短超时，add 异步；无配置则空操作。
3. 先手工写入 5 条偏好，用现有可乐用例验收 Prompt。
4. 再决定 Cloud 试用密钥还是自建开源 MemOS。
5. 客户话术补一句：记得你常买什么；你说忘掉就忘掉。
6. 用同一组货架样张给备选多模态打分，通过再切 `backup` / `primary`，不先为换模型改眼镜。
